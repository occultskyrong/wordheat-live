# 前端视觉与交互精修设计

日期：2026-10-27  
范围：仅 `apps/web/**`；不改变 API、业务状态、路由语义或 OBS 公私边界。

## 决策

采用“证据驱动精修”，保留现有墨蓝、青绿、琥珀色视觉体系，不做全站换肤。用户已授权直接理解并执行后续前端修复，不再逐项确认。

备选方案为仅做 CSS 快速修补和全站视觉重做。前者无法完整处理导航与交互反馈，后者回归面过大且缺少证据支持，均不采用。

## 已观察问题

基于 1440×1000 桌面与 390×844 移动截图：

1. 移动端主播台四项指标单列，核心回合操作被推到首屏之后。
2. 顶部导航可横滑但缺少视觉提示，后续页面不易发现。
3. 移动端题库四个筛选控件单列，题目列表过晚出现。
4. 已发布题目的只读输入与可编辑草稿输入外观过于接近。
5. 次级文字、较小字号与触控目标需要对比度和移动端复核。

## 设计

### 移动首屏与内容密度

- 仅在小屏将主播台等指标网格调整为两列，保留桌面布局。
- 缩小移动端页眉间距和指标卡内部垂直间距，不牺牲文字可读性。
- 题库搜索独占一行，分类、难度、状态使用紧凑两列布局；筛选语义和状态不变。

### 导航可发现性

- 保留所有七个页面入口及当前 NavLink 行为。
- 为移动横向导航增加不遮挡内容的边缘渐隐；仅在实际存在对应方向的可滚动内容时显示。
- 使用滚动容器状态和 ResizeObserver 更新边界，不以固定页数或屏幕宽度推断。
- 当前项可在路由变化时滚入可见区域，避免刷新后当前页面藏在屏外；尊重减少动画偏好。

### 状态与可访问性

- 为 `readonly` 输入提供克制的背景、边框、文字与光标差异；不禁用字段，不改变表单提交或焦点行为。
- 在实际背景上检查 `--faint` 等文字颜色的对比度，必要时小幅提高亮度。
- 移动端主要按钮、输入和导航触控目标至少 44px；紧凑的次要控件不机械放大。
- 保持明确 `:focus-visible`，不改变现有键盘弹窗和减少动画语义。

## 验证与停止条件

- 先补移动布局、导航边界和只读外观的回归检查，再实现。
- 以相同路由、数据和 1440×1000／390×844 视口采集前后截图。
- 复查主播台、题库、设置、评分、回放、复盘和弹窗；检查横向溢出、键盘焦点与减少动画。
- 每轮运行组件／单元测试、生产构建、浏览器测试及 OBS 公开包检查；停止临时服务器。
- 当剩余差异仅是主观偏好、没有可用性证据支持，且完整验证通过时停止迭代。不宣称 Windows、OBS CEF 或真实平台验收通过。
