# Mac 后端运行与维护

适用后端契约 `LW-C1/1.0.0+LW-BE/1.1.0`。本机业务 API、离线 scorer、公网 relay 使用三个独立 Python 环境。本文只覆盖后端；Windows 的 SID、DPAPI、UAC、SCM、Job 和 OBS 实机交付继续由对应原生工程验收。

## 当前本机资源

代码根为 `/Users/jiachenclaw/code/wordheat-live`。API 配置为根 `.env`，relay 配置为 `deploy/public-relay/.env`，均仅当前用户可读写。DLC 已登记的 `postgres` 容器承载 `wordheat_test`、`wordheat_relay_test`；`wordheat_restore_test` 是已登记的独立恢复验证库。日常启动不创建、重建、停止容器或接管其他数据库。

模型来自 `.local/models/bge-small-zh-v1.5`，以 `resources/model-manifest.json` 冻结的文件、revision、维度和归一化规则为准。启动只校验和加载本地文件，不补下载。词库、校准和审核结果由后端发布流程产生；示例词对及合成负载不产生人工 G1-Q、G0、G1-R 或 G2 放行证据。

账号停用/启用只在受控 CLI 执行（首发 Web 不做角色 CRUD）。停用会写入 `operators.disabled_at` 并立即撤销该账号全部会话，启用清除该时间：

```sh

apps/api/.venv/bin/python -B apps/api/app/cli.py --root /Users/jiachenclaw/code/wordheat-live enable-operator --username operator
```

单个 operator 会话在 8 小时内可随时撤销（凭据泄露时无需等过期）：`GET /api/v1/auth/sessions` 列出本人会话（带 `current` 标记，不返回令牌材料），`DELETE /api/v1/auth/sessions/{session_id}` 撤销。撤销后该会话的 HTTP 请求返回 401，其 STUDIO WebSocket 由服务端以 4403 关闭；撤销他人会话需要 `maintenance.request`。展示侧通过 `DELETE /api/v1/display-tickets/{ticket_id}` 撤销票据，相关 display 会话与 WS 同时失效。

## 无前端的业务调用顺序

1. 登录 `POST /api/v1/auth/sessions`，保留角色 Cookie 和响应中的 CSRF。
2. 创建题目草稿；分别提交 calibration 和已锁定标注的 blind 评测任务，轮询真实终态。审核决定绑定 evaluation_id，发布绑定 approved_version。已发布版本不可原地修改。
3. 创建 `mode=rehearsal, run_purpose=local` 场次。创建/兑换 primary 票据，展示协议消费者取得快照并通过 DISPLAY WebSocket 完成 resume_ready。
4. start 消费后端持久预选，自动建立首轮。人工试词只代表当前操作者；多参与人合成负载使用服务器 Python 的本 boot 私有 permit，浏览器不能提交平台 UID、身份或分数。
5. 非命中进入持久评分队列，由真实 scorer 异步处理；审核别名/答案精确命中才获胜。暂停、提示、恢复、VOID、超时、自动续轮和 end 均使用资源版本及幂等键。
6. 真实协议消费者收到授权 effect 后分别提交 received、processed。快照和重放不等于呈现完成；processed 不是由本机持久 ACK 推定。
7. 查询消息 trace、场次统计及固定 snapshot 的分钟/轮分页与 CSV。CSV 要带 snapshot_id，过期/驱逐后重新取首屏，不能拿旧 cursor 静默换快照。
8. 回放上传脱敏记录后创建独立 replay 场次，start/pause/resume/cancel 作用于回放任务；不写正式平台账本和履约。

请求、命令、错误码和闭合字段以 `packages/contracts/openapi.yaml`、独立 WebSocket/原生协议 Schema 为准。成功受理不等于评分、展示或平台履约完成，查询对应持久状态。

## 原生维护与正常退出

原生控制连接使用私有 Unix socket 和实际 OS UID/PID/程序身份。CLI 先核对服务端身份，再读取隐藏密码。下列命令不把密码写入参数，也不依赖重新读取 `.env` 获取短期身份。

```sh
apps/api/.venv/bin/python -B apps/api/app/cli.py --root /Users/jiachenclaw/code/wordheat-live native-control status --username operator
apps/api/.venv/bin/python -B apps/api/app/cli.py --root /Users/jiachenclaw/code/wordheat-live native-control request --username operator --runtime-command stop --reason 正常退出
```

维护采用 request → prepare → 审阅安装实例/计划摘要/产物摘要 → confirm。五类操作为 backup_local、verify_local_backup、restore_new_instance、upgrade_app、switch_model。HTTP 只能请求，不能传 confirmed、任意路径、程序或 URL。取消尚未确认的维护不会停止活动业务。

prepare/confirm 使用已登记的 logical artifact/source/target ID，服务端只在私有目录解析该 ID。文件、空间、版本和签名在确认前后复核；变化后必须重新准备。确认字符串显式绑定安装实例与计划 fingerprint。

正常停止先关闭输入并收尾场次/平台任务，再回收本产品 API/scorer；独立 watchdog 在 API 卡住时按预算强制回收自有进程，并保留未确认状态供下次恢复。数据库容器及其他进程不属于该进程组。

## 备份、恢复与模型切换

数据库备份和事实校验共享同一个 PostgreSQL READ ONLY / REPEATABLE READ 导出快照。归档、无密码角色计划和运行上下文位于私有备份目录；Web 只看到脱敏位置提示。备份不授予发行签名或平台授权。

独立恢复目标必须预先登记为非活动 WordHeat 专用库，校验库 marker、实例、所有者与最小权限角色。恢复不覆盖源库，不执行归档中的任意角色脚本或程序。验证表数据、迁移摘要和恢复后的授权失效；迁移中的已安装固定函数/trigger 仅按可信打包定义核对，不能把任意归档函数放入白名单。验证用自有命名空间按任务归属清理；请求保留的新实例不自动切换为活动实例。

模型切换要求签名模型清单与联合题库/校准资源。需要不同模型身份时完整关闭旧套件，使用新 boot 启动并真实预热，再导入和激活联合资源。旧轮、缓存、授权不随文件指针自动继承。失败保留维护/恢复状态，不偷偷回滚并继续计分。Windows 受保护 EXE 激活和独立 PG 服务建立仍需要 Windows 原生 executor。

## relay 与官方模式

relay 使用独立库和私有 `.env`。平台 AppSecret、推送验签 secret、身份映射 HMAC key、RSA 请求密钥及平台验签公钥各有独立用途；不能混用或下发本机。短 access token 和设备 token 只保存在内存。外部调用默认关闭。

官方公开协议已实现回调验签、批量持久化、令牌、任务 start/query/stop、履约 ACK、直播间核验与可选 RSA 签名。官方评论的测试来源不能靠 body.is_test 或缺省值推断；缺少受信来源证据时拒绝正式归类。

本机设备初始化与配对通过 device.prepare/confirm、pair.prepare/confirm 完成。长期设备 seed 仅保存于本机私有 `.env`；配对需要明确管理用途签名、真实 launch token、服务端房间核验及设备私钥 PoP。一般 live_grant 不具有配对管理权限。Native trust.prepare/confirm 仅导入规定签名包，freshness proof 必须来自实时 challenge。

正式开播仍需正确房间绑定、当前完整候选、对应 profile 的 gates/grant、租约与展示就绪。环境名、存活健康检查、测试 fixture 和本机负载报告均不能生成这些证据。真实平台开通/授权及 Windows 正式包链路在相应环境取证。

## 故障排查与数据保留

先查询 runtime 状态、command_id、job_id 或 message_id 的脱敏 trace。source/frame、transport.persisted、display.received、display.processed、平台履约分别核对。6 秒失联、5 秒运输屏障未齐、序号 gap 或来源内容冲突均进入明确故障，不跳游标追分。旧备份落后于 relay 保留点时展示 RPO/缺口，受控结束旧场后新开。

原评论 7 天、脱敏 trace 30 天、无评论/UID/答案的最终聚合 90 天，由后台维护任务处理；pending 引用、去重及 ACK 证据有保护。查询快照最长 24 小时，配额、pin、CSV 大小/时限和清理按 Spec 固定。生产统计只接受服务端核验的 official+production 且非平台测试来源。

## 容量、限流与实测入口

本机声明容量为 **2 个新独立词/秒 × 1800 秒零拒绝**；4 词/秒是实测临界（30 分钟运行出现显式 429 与 RESULT_STALE），6 和 10 词/秒明确不支持。完整数字、失败证据与环境限制见[交付核对](../acceptance/20261026%20-%20后端Spec%20-%20Mac交付核对.md)的容量附录。

冻结的受理参数：全局 5 事件/秒、burst 5；单用户 1 条/秒、10 秒内 5 条；同轮同词一次；评分队列 200、批次 32；演练并发入场事务 4。超出并发上界的请求立即返回 429 `RATE_LIMITED`，不会先受理再丢弃；评分超过 2 秒截止写 RESULT_STALE 终态，不补零分。

容量测试是显式 opt-in，默认不跑，会清空专库表并要求真实模型、两套解释器和整段独占：

```sh
cd /Users/jiachenclaw/code/wordheat-live/apps/api
WORDHEAT_TEST_CONFIG=/Users/jiachenclaw/code/wordheat-live/.env \
WORDHEAT_RUN_CAPACITY=1 \
WORDHEAT_TEST_MODEL_ROOT=/Users/jiachenclaw/code/wordheat-live/.local/models/bge-small-zh-v1.5 \
WORDHEAT_TEST_SCORER_PYTHON=/Users/jiachenclaw/code/wordheat-live/apps/scorer/.venv/bin/python \
WORDHEAT_LOAD_REPORT=/abs/path/report.json \

.venv/bin/python -B -m pytest tests/integration/assembly/test_real_time_capacity.py -q -s --tb=short
```

运行期间不要同时压测或做备份/恢复，否则尾部时延与拒绝计数不可比；报告分别记录受理、轮间拒绝、限流、评分终态、`accepted_without_processed`、`pending_at_end`、来源分区与进程 CPU/RSS。本机 PG 数据目录位于容器绑定挂载，checkpoint 写入可能达到数百秒，这是本机声明容量低于原 Spec 目标的主因；Windows 本机 NVMe 目标须按 WT08 复测，不复用本机结论。Windows/OBS 共机 30fps、GPU 和编码丢帧不能由 Mac 后端测试推定。
