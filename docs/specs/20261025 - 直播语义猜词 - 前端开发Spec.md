## 0. 仅页面实施补充口径

本节用于约束“仅针对前端页面”的实施批次，不改变首发F01–F60、W01–W18范围，不替换WP03–WP36的依赖、主责或done_evidence，也不授予真实后端、平台、部署或验收权限。与后文页面卡、C1契约冲突时，仍以后文共同契约和权限边界为准；本节只补充当前工程条件下的完成定义。

### 0.1 开发就绪结论

本Spec已足够指导八类页面的布局、组件、交互状态、错误UX、公私隔离和合成fixture测试，但不能单独替代可执行OpenAPI、构建锁文件、真实API或外部验收。当前审查事实如下：

| 项目 | 当前可用依据 | 页面批次处理 |
|---|---|---|
| 页面与交互 | P01–P08页面卡、三条状态轴、API消费表、错误UX和FE-A01–23 | 可直接作为页面实施依据 |
| 共同契约 | 前后端相同`LW-C1/1.0.0`、`schema_version=1`快照；路由与接口消费表一致 | 只消费已明确形状；未精确展开的DTO不自行补造wire字段 |
| 视觉资料 | 主播控制台、直播观众画面、评分实验室三张概念图及其余页面文字规格 | 统一使用一套高可读主题；概念图不等于最终视觉或真机验收 |
| 生成类型 | WP03 OpenAPI/Schema和`src/api/generated/{public,private}.ts`尚未落地 | 保持generated目录不伪造；页面批次只定义fixture视图模型 |

| 外部验收 | G0认可输入/聚合反馈、OBS CEF/手机、G1-R、固定RC和G2待验证 | 不以截图、组件测试或开发服务器结果替代 |

### 0.2 页面批次的文件与数据边界

- 演练fixture继续放`src/test/fixtures/`；页面专用的本地fixture适配器和视图模型可放`src/api/fixture/`。视图模型只服务页面展示，不冒充OpenAPI生成DTO，不新增或猜测wire协议字段。
- `src/api/generated/`只接收WP03共同契约的真实生成物。页面批次不得手写`public.ts/private.ts`冒充生成结果，也不得为了页面方便另建一套漂移的public/private线上DTO。
- 本地fixture适配器与后续真实client应面向相同页面查询/命令端口；页面组件不直接读取fixture JSON。真实client就绪后按WP替换适配器，不修改业务权威归属。
- 所有fixture均为合成数据，并在全局、页面或结果区域清楚标记“演练/合成数据”；不得包含真实秘密、未发布题、原始平台UID或伪造的验收记录。
- 页面批次不请求不存在的真实API，不伪造命令已应用、模型已评分、回执已履约、平台已接通或readiness已通过。按钮可以驱动明确的本地演练状态，但结果必须保持演练标识；未实现的实能力显示“待真实API接入”，不能显示假成功。
- OBS仍使用独立display入口和公开视图模型，不得导入Studio router、私有fixture、私有题库或未揭晓答案。私有页面的合成谜底同样不得进入public bundle、source map、日志或OBS URL。
- WP13除机器清单列出的页面/组件外，包含本Spec §6要求的display bootstrap、syncMachine、receiptQueue及邻近单元测试；`planned_files`不是删减这些必要行为的依据。页面批次可先验证其合成状态机，真实快照/回执仍在WP21及后续验收。

### 0.3 页面批次完成定义与禁止声明

页面批次只有同时满足下列项，才可记为“页面层完成”：

1. 八类页面路由可访问，主要元素和P01–P08规定的空、加载、错误、冲突、pending及故障演练状态可操作检查。
2. 公共主题、键盘/focus、纯文本渲染、OBS双画布/安全区/减少动画及public/private入口隔离得到组件或构建检查。
3. 本地演练命令、版本冲突和事件分支不越权计算真实分数、赢家、积分、截止时间、租约或readiness；所有合成结果可追溯至fixture。
4. 组件/页面测试与生产构建实际执行并保留命令、结果和未覆盖项；测试命令以落地后的工程README为准。

“页面层完成”不等于WP06、WP13、WP14、WP15、WP17或WP30各自done_evidence全部满足，不更新这些工作包为完成，也不等于实际API接线、完整八页安装Alpha、OBS CEF、固定RC或真实平台通过。WP15/WP17仍以实际API对账为包内条件，WP30仍以实际双端故障为包内条件；WP21必须重新构建同版完整Alpha，WP34/WP35/WP36继续保留原验收要求。

本轮如只执行页面批次，交付说明必须分别列出“已实现的页面能力”“仅合成演练的能力”“待真实契约/API/Windows/平台验证的能力”，不得以单一“前端完成”概括。

## 1. 要解决的问题与实现边界

| 问题 | 具体前端方案 | 可观察的完成条件 |

| 主播不知道能否开播 | P01把数据库、模型、题库、relay、租约、主展示与G0/G1/G2/RC逐项显示；后端返回三种 readiness 权威布尔值 | 依赖失败时正式按钮禁用，能读到具体原因，不把“进程存活”显示成“可正式开播” |

G0真实输入形态、认可客户端/包体与聚合反馈形式，G1评分质量/OBS共机资源，G2真实直播为外部验证门槛。设计可先按冻结fixture落地；未通过门槛时保留“可演练/可测试采证”的实际边界。测试环境接通、安装Alpha、绿色组件测试都不等于可正式上线。

## 3. 共用交互、权限和安全

所有页面采用同一套高可读主题；F61多主题/自定义配色不首发。P08的配色是该主题的固定语义色说明和对比预览，不提供任意调色编辑器。按钮以文本表达状态，颜色不是唯一信息。表格保留标题、单位、版本/采样时间；未知值显示“暂无数据/尚未测量”，不能填0或假绿色。

### 3.1 权限与身份

私有入口先调用 `GET /api/v1/auth/sessions/current` 取得actor及operator csrf_token；401显示登录面板，登录响应返回operator csrf_token，成功后重取current校验身份。actor形状为{actor_id,display_name,permissions[]}，权限由后端返回并校验，前端权限仅控制可见/禁用。操作能力码固定：session.control控制场次/回合，puzzle.edit编辑题库，puzzle.review审核发布，diagnostics.read读取诊断，replay.control执行回放，scoring.evaluate运行评测，maintenance.request请求维护，display.manage管理展示票据。角色名称仅用于文案展示，不按“主播/运营/管理员”文字、显示姓名或前端路由推断权限。缺权限显示只读数据及“需要××权限”的禁用原因，不把403当网络故障重试。

除首次 `POST /api/v1/auth/sessions` 登录与 `POST /api/v1/display-sessions` 一次性交换这两个唯一bootstrap例外外，所有已鉴权修改HTTP必须使用本角色Cookie及 `X-CSRF-Token`，同源 `credentials: 'same-origin'`；业务命令附 `Idempotency-Key` 与 `X-Contract-Version: LW-C1/1.0.0`，读请求也声明契约版本。这两种bootstrap请求没有既有角色CSRF，后端必须精确校验Host/Origin、限定application/json、拒绝跨域CORS，并实施体积/速率限制；这不是其他POST的CSRF豁免。operator Cookie名 `lw_operator`、display Cookie名 `lw_display`，两类有效期均为28800秒，由后端设置HttpOnly、合适的SameSite/传输安全策略及scope，前端JS不读取Cookie值。

命令body固定 `{command,expected_version,args}`，返回 `{command_id,status,resource_version,state,error}`；status为 `pending|applied|failed|cancelled`，error为null或{code,message,retryable}。一次用户意图创建一次幂等键，超时后“查询状态/重试原命令”复用原键原body；编辑内容后必须新键。pending只显示“处理中”，不预先改 round.status或播放效果；保存command_id并通过GET /api/v1/commands/{command_id}轮询到applied/failed/cancelled，STUDIO command.updated可加速终态更新但不能代替断线后的查询。只允许同actor/resource查询；failed显示结构化error、cancelled显示未应用，均重取资源状态后解锁按钮。旧version冲突重取权威状态，关闭失效弹窗，要求基于当前对象再次发起；不自动把旧命令套到新轮。

### 3.2 展示票据与构建隔离

P08创建范围限定的只读票据，链接把一次性ticket放fragment。OBS入口读取fragment到短命内存后，先用history.replaceState清掉fragment，再 `POST /api/v1/display-sessions` 交换；失败仅显示重新生成链接指引，不把票据放query、Referrer、错误截图或console。引导票据TTL为60000ms，重复、过期、撤销不能自行恢复管理权限。兑换与刷新后的 `GET /api/v1/display-sessions/current` 均返回 `{display_instance_id,render_generation,session_id,purpose,receipt_csrf_token,expires_at}`；purpose仅 `primary|preview`，与场次run_purpose是不同维度。receipt_csrf_token只存当前展示实例内存，POST receipts使用该display角色token；刷新从display current取回，绝不借用operator csrf_token。Cookie有效但current失败时停止回执并重新授权，不从query/localStorage拼token。后端返回的主展示实例 `display_instance_id` 和 `render_generation` 由服务端授予；预览与主展示身份由后端授予，不由浏览器参数“primary=true”决定。

展示会话只绑定一个场次。撤销 `DELETE /api/v1/display-tickets/{ticket_id}` 必须同时令关联展示会话及既有WS失效；P02清空旧内容并显示“展示授权已失效”。新场不能复用旧场Cookie范围或旧票据，主展示重置代次后旧实例回执被拒绝。预览可消费同类public投影，但绝不发送履约received/processed。

原生 `WebSocket` 构造器无法添加Authorization header，因此DISPLAY/STUDIO WS使用各自HttpOnly角色Cookie，后端精确校验Origin与Host。禁止把token放WS query，也不绕过Origin校验。前端仅连接部署manifest确认的同源地址；内部embeddings和relay接口不由浏览器直连。

public build依赖图只允许public类型、display API、public stores和OBS组件。构建检查扫描chunk/source map/fixture依赖，禁止private-state客户端、答案题库、aliases、target_vector、neighbors、private_puzzle_id、platform_uid、platform_secret、debugAnswer；生产public不发布私有source map。测试fixture使用合成内容，示例答案只可放明确REVEALED fixture，不能把真实未发布题装入静态包。

### 3.3 文本、导出与访问性

昵称、猜词、解释、错误消息均以React文本节点渲染，不用dangerouslySetInnerHTML、不解析Markdown HTML、不自动生成外部链接。长文本按公开契约限长显示，完整诊断仍须权限；使用溢出省略和详情面板，不能裁掉状态。原始平台UID不出现在public数据、DOM、URL、日志和复制按钮；trace仅用脱敏参与者ID。

CSV导出优先消费后端脱敏导出能力；若前端从analytics合法结果生成CSV，固定字段白名单、UTF-8、标准双引号转义，所有以 `= + - @` 开头或前置制表/回车能引发公式的字符串先作为文本保护，数字单元仅接受有限数值。文件名只含安全场次标识与日期；不导出Cookie、私有答案、原始UID、平台secret。生成前显示字段/来源模式确认。CSV导入不在前端擅自发布，前端校验仅改善提示，服务端报告是权威。

后台支持键盘操作与清楚focus，确认框限制焦点并支持取消；输入label和错误关联；加载区aria-busy，关键故障使用有限aria-live，避免高频猜词反复朗读。OBS减少动画同时兼容系统prefers-reduced-motion，所有语义在静态文本可读。没有成功反馈的操作不能仅静默关弹窗。

## 5. 回合、传输、启动器状态与计时

### 5.1 三条状态轴

`round_states`完整枚举为IDLE、PREPARING、RUNNING、PAUSED、DRAINING、REVEALED、INTERMISSION、FAULTED；`transport_states`为DISCONNECTED、CONNECTING、CONNECTED、RECONNECTING、FAULTED。launcher状态独立，不能把READY_OFFICIAL当当前round RUNNING。

| round/transport组合 | 观众画面 | 主播动作与禁止项 |
|---|---|---|
| null round / IDLE | 待开始、规则占位，不显示旧短码/答案 | 创建合格新轮，不能resume空轮 |
| PREPARING | 准备中，不显示已计时/可参与 | 显示模型/窗口/展示准备项；不开第二轮 |
| RUNNING+CONNECTED | 正常规则、短码与截止倒计时 | 后端允许pause/skip/void/hint；不在前端提前判胜 |
| PAUSED | “已暂停”，使用remaining_ms冻结 | resume需后端确认；暂停前已受理结果可能仍回填原轮，不能把每个更新误判为违规 |
| RUNNING+RECONNECTING | “数据重连中，回合时间继续；结果待确认” | 正式提交冻结由backend执行；UI禁依赖旧租约动作，不把倒计时冻结成手动暂停 |
| DRAINING | “正在收尾”，不继续邀请输入该轮 | 等完整权威结果，计时归0不自行宣判TIMEOUT |
| REVEALED/INTERMISSION | SOLVED显示赢家；TIMEOUT显示未猜中；VOID显示作废与积分冲销；INTERRUPTED显示故障中断保留已提交积分 | 自动续局计划显示服务端next_start_at；中断路径必须人工确认新轮，不无提示沿用短码 |
| FAULTED或不可恢复transport | 清楚故障遮罩、保留已知状态的时点 | 修复/停止/恢复由backend给出许可；禁止本地按钮直接清故障继续 |

INTERRUPTED与VOID都是终结reason而非新round state。中断前若已原子SOLVED结算，界面保持原SOLVED，不因随后离线改写。relay达到连续6000ms通信失败、运输收尾超过5000ms、睡眠/重启、租约到期、不可补齐gap时由backend中断；前端不能凭一次WS close就自终结，也不能凭WS open就自恢复计分。lease TTL15000ms、安全余量3000ms是backend保守授权逻辑，页面只显示事实与原因。

### 5.2 权威倒计时

clock字段固定 `{time_origin,deadline_at,remaining_ms}`；time_origin仅 `relay|local_rehearsal|local_replay`。UTC RFC3339毫秒字符串先校验再解析。RUNNING使用权威deadline；PAUSED使用remaining_ms；IDLE无round。snapshot的server_time与clock必须一起采用，不能用浏览器加载时间起新表。

Clock组件在取得server_time时记录 `performance.now()` 基准与估算往返不确定度，再用 `estimatedServerNow = baseServerMs + (performance.now() - baseMonoMs)` 推进。显示 `max(0, deadlineMs-estimatedServerNow)`；仅用于画面，不发timeout命令、不决定赢家。刷新、系统时钟回拨、标签页节流后从新快照/heartbeat校准；不使用Date.now逐秒相减维持权威窗口。前端估算不确定度超过500ms时显示“时间校准中”，请求新状态，正式可用性仍由后端决定。客户端不因本地慢一秒延长正式deadline。

收到完整round事件后同步替换deadline/version/window_epoch；版本更小的旧事件不覆盖新状态。INTERMISSION只按next_start_at显示倒计时，到0显示“等待下一轮确认”，后端发round.started才更换短码。

### 5.3 Launcher展示边界

Launcher原生实现归 `R/apps/windows-launcher` 和WIN/BE；FE只在P01/P08的LauncherStatus消费runtime/status，不能据此选PyQt、WebView2或把React启动壳当完整原生Launcher。OBS真实运行在CEF，WebView2检查不能代替CEF。

| launcher状态 | Web文案/可用动作 |
|---|---|
| STOPPED | 已停止；引导使用已安装原生入口，Web不自行spawn |
| CHECKING | 检查安装实例/版本；禁开始 |
| DB_READY | 数据就绪，仍待API/模型；禁正式开始 |
| STARTING | 启动中，显示实际组件和等待时间 |
| WARMING | 模型预热中，显示manifest与进度事实 |
| READY_REHEARSAL | 可演练；正式仍取决于can_test_live/can_go_live |
| READY_OFFICIAL | 运行前提具备；仍检查本场readiness，不等于已开播 |
| RECOVERY_REQUIRED | 待主播确认恢复；展示旧轮和原因，禁静默续局 |
| MAINTENANCE | 维护中；禁开场/开轮，显示当前维护阶段 |
| FAULTED | 明确错误与修复建议，不无限转圈 |
| STOPPING | 停播/排空中，显示后端真实阶段，不先提示退出成功 |

API30000ms、模型120000ms、关闭排空15000ms为设计默认。重试延迟1/2/4秒、最多3次重试（不含首次，最多4次启动尝试）由native执行，耗尽后熔断且正式轮不自动复活，FE不建立另一套拉起循环。专用PG、OBS不归Web控制，维护界面不提供停止既有PG或OBS按钮。

## 6. 实时同步、幂等投影与真实渲染回执

### 6.1 数据协议与恢复算法

`seq`、window_epoch和所有generation均为非负十进制字符串，比较使用BigInt，不能Number、parseInt或字典序；version是非负integer。DISPLAY流以session+DISPLAY独立连续编号，STUDIO流以session+STUDIO独立连续编号；两者数字相同也不是同一事件。relay_stream_seq是数据和屏障的运输序号，不能拿它作为前端seq、round.version或时间戳。

syncMachine内部阶段是本机UI状态，不增加wire enum：bootstrap、snapshotLoading、resuming、live、resyncing、unauthorized、failed。过程如下：

1. 有效display Cookie刷新先GET display-sessions/current恢复本角色身份/token，不再使用已经消费的fragment；仅无有效身份才兑换新票据。随后GET public snapshot，验证schema_version、contract_version、session_id和完整白名单；round可为null。原子写入displayStore，游标设snapshot.as_of_seq，禁止仅拼接旧对象残留私有/旧轮字段。snapshot.pending_effects仅为待办描述，不授予新代次credit，不进入履约队列或发送回执。
2. 建立DISPLAY WS并发送`resume`，`after_seq`取刚取得的as_of_seq（十进制字符串）；服务端用该场次授权识别频道。原生WS由Cookie鉴权，无token query。STUDIO必须先GET /api/v1/studio/sessions/{session_id}/snapshot，在同一原子快照中取得私有投影与独立STUDIO as_of_seq，再resume；不能用live-sessions详情或单独private-state拼接游标。studio快照字段为schema_version/contract_version/session_id/mode/run_purpose/as_of_seq/server_time/public_view/private_round/session_rules/next_rules/readiness/pending_commands；private_round可含答案，仅进私有cache，public_view仍是public白名单。顶层as_of_seq专属STUDIO，不把public snapshot的as_of_seq传给STUDIO；除共同投影事件外，STUDIO额外接收command.updated/runtime.updated/diagnostic.updated/job.updated，分别更新私有命令/runtime/诊断/任务状态，DISPLAY解码器不接受这些类型。
3. RESUMING期间只按seq顺序恢复replay投影；replay.effects仅为描述，不授予新generation额度，不进履约队列且不发received/processed。catch-up推进不等待processed，避免READY前互等。事件type仅接受seed的round.started/paused/resumed/draining、guess.feedback、ranking.updated、hint.revealed、round.revealed、intermission.started、connection.status。schema或contract不匹配进入failed并停回执，不能忽略新字段造成假正常。
4. 每事件先校验session和envelope，再比较seq。`seq == last+1`才应用并推进；`seq <= last`视重复或旧投递，按event_id/内容指纹防冲突，不重复动画/变更分数；相同seq内容不同为协议故障。`seq > last+1`说明缺口，停止继续应用，重取快照再resume，不能跳游标到最大值。
5. 服务端`resume_ready`含upto_seq/server_time/render_generation/pending_effects，验证upto_seq与已连续应用游标一致才恢复live；此前禁received/processed。DISPLAY primary握手时由服务端为新连接轮换render_generation并关闭旧连接，到一致边界后ready才授予本连接新代次及至多128个真正待处理授权；旧批次不得改代次重发，只把本次ready授权入履约队列，实际处理后生成新批次。STUDIO对应两字段必须null/[]，preview不履约。heartbeat每2000ms只校准时间/状态，latest_seq不是跳游标许可；`resync_required`按min_seq/latest_seq诊断并重取快照。保留期外、decode失败、不可补齐gap均先显式故障，再按后端许可恢复。
6. 新round.started只原子替换round-scoped视觉状态并清旧轮短动画；独立的unfinished effect/receipt队列完整保留，不能因换轮丢弃未处理反馈。PendingEffect携带origin_round_id/window_epoch/display_name/solved；旧轮effect只在“历史待确认反馈”区静态呈现，不改新轮排行榜、倒计时、短码或提示，不播放旧胜利。同generation换轮保留已授权未履约队列；连接恢复时旧generation授权失效，snapshot/replay描述不得混入新队列，必须等本次ready授权。不能把snapshot之前但未processed的效果当完成。round.version倒退、错误window_epoch、错误session的结果隔离并留脱敏错误，不应用到当前轮。
7. WS断开采用1/2/4秒有界退避重连；重新连接始终由快照/resume握手恢复，不以onopen直接标live。只有用户授权还有效、后端可恢复时重试；票据撤销、CONTRACT_VERSION_UNSUPPORTED、不可补齐gap不无限重连。

`ranking.updated`发送完整ranking，round.*发送完整public round/reveal，connection.status完整覆盖transport，guess.feedback payload固定{feedbacks,effects}，feedbacks为Feedback[]、effects为PendingEffect[]；不是把snapshot.latest_feedbacks字段原样猜作事件payload。积分、参与人数、分数均“替换绝对值”，不执行`points += delta`；重复replay不会再加一遍积分。去重索引有界且按场次清理；长期历史正确性由持久快照与seq承担，不能靠无限增长Set。

### 6.2 回执实施流程

五种确认必须分别显示：中继HTTP持久确认、本机persisted ACK、display received、display processed、平台履约结果。前端只产生第三和第四项，不向relay直接报完成，不把收到WS或React setState当完成。

receiptQueue仅在primary已验证resume_ready后启用，只接收ready及LIVE事件中后端已预留credit的effects授权；snapshot/RESUMING replay中的同形描述不能入队。队列绑定该连接获授的当前display_instance_id/render_generation，使用该实例receipt_csrf_token作为X-CSRF-Token；没有token时先GET display-sessions/current，不借operator身份。`receipt` body字段固定 `display_instance_id,render_generation,batch_id,stage,deliveries`；stage只有received或processed；每项delivery为 `delivery_id,client_time,feedback_id`。client_time为UTC RFC3339毫秒且仅作诊断，不能证明真正上屏。batch_id生成后重试保持相同body，依赖delivery_id幂等；pending网络失败保留待发，不凭HTTP超时重复展示。

- **received**：完整解码并校验反馈，建立delivery→feedback映射，主展示已进入可处理队列后上报。没有解析成功、授权不符、被队列拒绝或preview，不上报received。
- **processed**：对应反馈组件已commit、当前主展示文档可见、目标卡/合法聚合文本实际存在且未被错误边界遮挡，再经过浏览器绘制机会核验可呈现，才将该feedback映射的deliveries组成processed批次。动画不是必要条件；减少动画模式的静态有效反馈也可完成。requestAnimationFrame本身不是证明，需与实际DOM、可见性、当前实例和effect状态一起判断。
- **隐藏/卸载**：OBS隐藏后若CEF卸载或document隐藏，不发送processed；仅内存排队/后台DOM更新不能冒充观众看见。恢复时snapshot/replay只还原描述，等ready授权后按G0认可反馈实际展示再确认。前端不能证明用户眼睛看见，平台认可客户端/可见性判定仍需G0和真实CEF验证。
- **刷新**：内存receipt状态清空；snapshot/replay仅恢复待办描述，收到resume_ready授权才可入履约队列；实际处理只重建静态反馈、不重播旧庆祝。已经processed的历史项不在前端靠缓存重报；未processed即便delivery_mode=replay也须真实处理。replay只是补发来源，不自动算履约成功。
- **连接/代次切换**：旧generation队列停止，旧连接由服务端关闭；有效Cookie走current→snapshot→resume，无需重用已消费fragment。以resume_ready的新generation和pending_effects对齐待办，完成项不复活；重新实际处理后生成新批次，禁止把旧batch改代次重发。
- **高峰合并**：队列上限、聚合粒度与获认可的最小反馈由G0对应玩法确定。首发组件支持有限列表和“另有N条反馈”等信息，但一行计数不能自行兑现每条平台履约；只有获认可且保留delivery映射的实际聚合反馈可processed。不能满足时反馈保持pending并告警/限容量，不以丢弃计数伪报处理完成。

队列项保留origin_round_id、window_epoch、display_name、solved及delivery映射，换轮不清空；旧轮静态反馈明确标来源轮，且不更新当前排名或触发庆祝。每个effect按feedback_id和delivery_ids去重。feedback状态包含scored、format_invalid、duplicate、rate_limited、round_closed、system_failed；无分状态必须显示对应原因。合法的失败/过滤反馈能否作为官方处理反馈由G0约定，UI不会把“不展示”自动当完成。P06提供received时间、processed时间、pending数量、失败重试及平台结果分栏，便于逐条对账。

恢复泵使用共同契约额度：每代次最多128个未processed授权、每效果最多32个delivery_id。RESUMING的snapshot/replay仅恢复投影与待办描述，不占新代次credit、不进入履约队列；补发可直接推进至一致边界，绝不等READY前的processed。resume_ready才发至多128个真正授权。LIVE guess.feedback.effects仅含后端已预留credit的授权；credit满时仍可发送视觉feedbacks但effects=[]，不据此伪造履约。只有processed释放额度，received不释放；之后后端按DISPLAY序号发guess.feedback（feedbacks=[]、effects为历史授权批次）续送，FE实际静态处理后再确认。旧generation授权重连即失效，同generation换轮仍保留独立未履约队列。不靠刷新领下一批、不丢弃/伪报；聚合仍需G0认可，调整限额须共同变更C1。

## 7. API消费表与错误到UX映射

### 7.3 标准错误交互

所有错误展示可读message和脱敏request_id以便排障；details只提取获准字段，不能直接JSON.stringify全量对象。可重试提示服从retryable和当前状态；无响应不能判断业务未执行，写请求重试保留幂等键。

| code / HTTP | UX与下一步 |
|---|---|
| AUTH_REQUIRED /401 | 清私有状态、转登录；P02按展示重新授权，不打开管理登录 |
| FORBIDDEN /403 | 保留只读范围，按钮禁用并说明权限；不重试变更 |
| DISPLAY_UNAUTHORIZED /403 | 停DISPLAY WS和回执、清旧画面，提示主播生成新链接 |
| PAYLOAD_TOO_LARGE /413 | 显示上传/请求超过上限，保留表单与文件名，按后端限额缩小后重新提交，不循环重传 |
| CLOCK_UNCERTAIN /409 | 显示“可信时钟未确认，暂停正式操作”；重取权威状态，不能改系统时间或自行延长deadline |
| INPUT_INVALID /422 | 对应字段错误；保留草稿；提交前聚焦首个错误 |
| RESOURCE_NOT_FOUND /404 | 该场/轮/任务不存在或不可见；停止轮询，提供返回列表 |
| ROUND_CLOSED /409 | 关闭旧轮动作弹窗、刷新当前轮；不把旧操作施加新轮 |
| ROUND_VERSION_CONFLICT /409 | 提示其他操作已改变状态，重新读取version；需再次发起当前意图 |
| IDEMPOTENCY_KEY_REUSED /409 | 请求内容和键冲突，停止自动重试，保留request_id排障；明确新意图才新键 |
| CONTRACT_VERSION_UNSUPPORTED /409 | 显示前后端版本不兼容，禁写/停事件回执；走受控更新，不容错猜协议 |
| RATE_LIMITED /429 | 显示限流/稍后重试；猜词不展示为低分；若有后端重试提示按其等待 |
| SCORER_NOT_READY /503 | 模型未就绪，禁新轮、活动轮服从后端暂停/故障；无假分 |
| DEPENDENCY_UNAVAILABLE /503 | 指明DB/relay/展示等细分依赖；显示最后有效时点；不伪称输入已持久或开播完成 |
| RELAY_GAP /409 | “数据缺口，旧轮已停止/待确认”按权威状态展示；不可跳到最新seq继续计分 |
| LEASE_EXPIRED /409 | “运行授权已失效”；禁正式动作，native重授权后需确认新轮 |
| WINDOW_VERSION_CONFLICT /409 | 窗口已变化，重取状态；不在前端重开已关闭窗口 |
| INSTALLATION_MISMATCH /409 | 设备与本机绑定不符，提示受控重绑；不能从浏览器修改installation_id绕过 |
| RESULT_STALE /409 | 结果属于旧轮/版本，标为未应用，刷新当前状态；不重送为新轮得分 |

## 8. OBS画面、可读性与性能规格

1080×1920为竖屏设计画布，1920×1080为横屏设计画布；两者都是本项目设计值，不是平台固定标准。obs.css使用固定设计坐标+等比例容器缩放，保持纵横比，不能以裁切丢规则换满屏。preview可加顶部/右侧/底部遮挡蒙版，主展示不把调试蒙版推流。

| 项 | 竖屏设计默认 | 横屏设计默认 | 实施/验收 |
|---|---|---|---|
| 设计安全区 | 顶120、底300、左右各64px，其中右侧可追加160px遮挡预览 | 顶64、底140、左右64px，右侧可追加160px遮挡预览 | P08可调整预览，最终以目标直播伴侣与手机实测遮挡为准；不是固定平台规范 |
| 规则/短码 | 48/64px，最多2行 | 40/52px，左上固定 | 入场即读懂；字体缩放在0.9–1.2内预览，越界时提示占位冲突 |
| 最新猜词/得分 | 64/72px，昵称36px | 56/64px，昵称32px | 常驻主视觉，不被庆祝/榜单盖住 |
| 计时/分类/提示 | 64/36/38px | 56/32/34px | 提示最多按3阶段布局；长文本允许换行而不推走规则 |
| 榜单 | 8词行，每行36px文字；场次前三32px | 8词行32px，侧栏前三30px | participant_count与积分标签分清；截断附可理解短称 |
| 解释/揭晓 | 答案88px、解释40px | 答案72px、解释36px | 最长获准解释换行，静态持续可读，不只出现2秒 |
| 动画 | 新纪录300–600ms边框，揭晓1–2秒 | 同左 | 减少动画即无位移/粒子，保留文本/轮廓/数值；不提供P1音效系统 |

使用随包且许可明确的字体，离线可用，禁止开播时依赖外站字体；禁止按用户文本远程加载SVG或HTML。词榜稳定key更新，条长和排名由绝对值渲染；动画不反复整体重建榜单。Clock局部更新，不让每帧setState重绘整页；只在可见时做视觉刷新，权威时间不依赖该刷新频率。最新反馈队列有界，聚合必须遵循G0认可形式；公开bundle不加载私有图表/题库/模型文件。

组件/Playwright用两画布、最长昵称/词/提示、无数据、重连、故障、揭晓、减少动画场景核对溢出与对比度。真正资源目标在WT08与G1-R记录CPU/RAM/GPU、OBS编码/渲染丢帧、独立词比例/缓存/吞吐，不用桌面浏览器fps代替共机资源。WT09必须测试OBS CEF隐藏卸载、场景切换、刷新与重连。手机最终看参与规则、最新反馈、榜单和状态能否读清，不能只缩桌面截图判通过。
