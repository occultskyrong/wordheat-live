## 01｜目标、责任与不可破坏的约束

后端总域分为本机业务API、推理进程、公网中继、Windows运行与交付四部分；BE与WIN仍是开发计划中的两个责任角色。本文覆盖二者的接口与实现边界，不把同一BE同时排成本机和中继两份产能。FE只调用本机API与展示/控制事件，不持有设备私钥、不直接连接中继或模型。

| 要解决的问题 | 实际方案 | 实现位置与验收 |
|---|---|---|
| BE-01 同一输入被重复计分、昵称被当身份 | 官方源ID和平台稳定身份映射；本机/中继两级唯一键；同人同轮同词逻辑去重 | inbox/participants；T03–05、WT14–15 |
| BE-02 评分慢、假分或相关词误判胜 | 独立真实模型、版本化缓存和校准；答案/审核别名精确匹配独立判胜 | scoring/rounds；T06–08、T21、WT04 |
| BE-03 并发猜中、截止、跳题竞争 | 持久序号、房间锁、不可变轮次、幂等命令和原子结算 | rounds/ledger；T09–14、T19、T27 |
| BE-04 私有谜底泄露或只读链接越权 | 不同授权会话、白名单DTO、独立DISPLAY/STUDIO事件流 | auth/realtime；T16–17 |
| BE-05 页面重连丢状态、重放庆祝、伪报履约 | 一致快照、按游标补发、pending_effects、真实分阶段回执与outbox | realtime/ack；T15、T20、WT09、WT20 |
| BE-06 Windows本机不能接公网HTTP | 公网中继验签持久化，本机主动WSS，不开放家庭公网入站 | relay/connector；WT14–18、WT21 |
| BE-07 租约重叠、旧连接或旧轮输入复活 | app/room唯一owner、原generation不可变、当前delivery代次、epoch栅栏 | relay leases/windows；WT13、WT16–19 |
| BE-08 本机时钟/迟到数据破坏公平性 | 正式时间来自中继；关闭屏障冻结输入边界，收尾内合法命中不因旧version消失 | relay windows/admission；T10–11、WT16、WT19 |
| BE-09 Windows安装/权限/升级损坏其他数据 | 专用PG、目标SID引导、DPAPI、目录ACL、Job、前向迁移和独立实例恢复 | Windows交付；WT01–12、WT22–23 |
| BE-10 演练被算成正式增长、故障无法定位 | 模式/来源从服务端固定，消息链路追踪、账本对账和脱敏指标 | operations/analytics；T26、WT22 |

必须保持：本机独占谜底、判胜和积分权威；云端不存指定谜底/题库向量/校准/账本（观众评论可能包含答案字面，但中继不持有题目答案映射）；一房间一个正式owner；网络至少一次投递，业务效果通过持久约束实现一次；失去证据时停止计分，禁止以mock、跳游标或伪造processed掩盖失败。

## 02｜工程模块与进程边界

`R` 表示wordheat-live仓库根。以下是后端规范要求的路径与职责，不据本文推断当前源码、运行或验收完成状态。

```text
R/apps/api/app/
  modules/auth/              # operator/display会话、权限、CSRF、一次性票据
  modules/sessions/          # 场次规则、模式、命令与版本
  modules/rounds/            # 唯一回合状态机、入场、判胜、收尾
  modules/inbox/             # 原始输入、规范化、身份、限流、去重
  modules/wordbank/          # 草稿/校准/审核/发布/CSV报告
  modules/scoring/           # 内部模型客户端、分数校准、任务
  modules/ranking/           # 积分账本、VOID冲销、榜单投影
  modules/realtime/          # 两个audience快照/事件、effects和回执
  modules/connectors/        # 主动relay连接、租约/窗口、持久游标
  modules/replays/           # 独立replay场次和控制任务
  modules/analytics/         # 场次聚合与安全导出
  modules/operations/        # trace、审计、runtime状态/维护请求
  infrastructure/           # DB、时钟、事务、outbox、限额与日志
R/apps/scorer/app/           # loader、encoder、batcher、health
R/apps/relay/app/            # ingress、leases、windows、streams、fulfillment
R/apps/windows-launcher/     # 原生状态、进程Job、bootstrap、DPAPI、维护
R/packages/contracts/       # OpenAPI、JSON Schema、同一版本fixture
R/resources/                # 审核模型manifest、题库、校准清单
R/deploy/windows-native/    # 安装器、构建、服务、升级/卸载验证
```

业务API单进程、模型单进程；Uvicorn采用Windows支持的asyncio，不启用生产reload。模型与数据库只监听回环/内部接口。网络IO和推理均不占用数据库长事务；所有外部操作先持久记录意图，异步执行并回写结果。中继与本机使用独立持久库，不共用一个连接字符串假装双端已经确认。

### 模式与就绪

session.mode仅`official / rehearsal / replay`，创建后不可热改；输入来源另记`official / manual / replay / bridge`，只由可信适配器填。另有不可变run_purpose：rehearsal/replay只能local，official必须test_live或production。create只核验身份、用途和平台绑定，产生CREATED草稿，不要求尚未绑定的primary展示或完整start就绪；随后可创建该场次展示身份，真正start再核验对应readiness，避免创建场次与展示就绪互相循环。不能靠任意is_test布尔取得资格。切测试/生产需结束旧场再创建新场，不在运行轮热切。人工试词被强制写入rehearsal，回放被强制创建replay场次，不接受浏览器指定分数、赢家或平台用户ID。

`readiness`含checks、gates及三个布尔：can_rehearse、can_test_live、can_go_live。checks为db/model/wordbank/relay/lease/display，gates为G0/G1_Q/G1_R/G2/rc_verified；每项返回status、reason_code、message。正式产品READY_OFFICIAL只表示official运行壳具备某条可用路径，真正“测试采证”与“正式开播”仍分别由can_test_live/can_go_live授权，前端不得从状态名反推上线通过。测试采证授权由受控测试场次与账号范围约束，避免G2未通过却永远无法采G2的循环。

## 03｜共同数据与接口规则

采用schema_version=1、contract_version=LW-C1/1.0.0。ID为不透明字符串；seq、stream_seq、generation与window_epoch在JSON中都是非负十进制字符串，不能用JavaScript Number承载；小范围资源version为整数。所有网络时间为带毫秒的UTC RFC3339，客户端时间仅用于诊断。

成功JSON统一`{data,request_id,contract_version}`；错误统一`{error:{code,message,retryable,details},request_id,contract_version}`。官方回调按平台要求响应，CSV下载采用text/csv与安全attachment，不包装为JSON。HTTP请求携X-Contract-Version；不支持的major返回CONTRACT_VERSION_UNSUPPORTED。任何用户输入仍在服务端校验，不依赖TS类型。

业务创建、命令、导入确认和评测创建要求Idempotency-Key。幂等键按actor＋method＋规范路径＋key唯一，绑定规范请求hash：同键同内容返回既有结果；同键不同内容409；必须先查既有幂等结果再校验新version，避免成功请求重试被错误拒绝。长期任务返回202和job_id，查询接口明确queued/running/succeeded/failed/cancelled与progress，不让长HTTP承担模型/导入全流程。

## 04｜认证、权限与本机安全边界

operator使用lw_operator、display使用lw_display两类HttpOnly会话，SameSite=Strict；HTTPS时置Secure，受控127.0.0.1本机HTTP不假定Secure cookie可用。服务只绑定127.0.0.1，校验实际配置的Host和精确Origin，不接受任意localhost别名、跨域通配或任意外部网页调用。已认证JSON状态变更带本角色X-CSRF-Token；GET不改变业务状态。

唯一的浏览器首次引导例外是POST /api/v1/auth/sessions和POST /api/v1/display-sessions：此时尚无角色CSRF，改为严格Origin/Host、application/json、无跨域CORS、大小/速率限制，并分别校验登录凭据或60秒一次性票据。登录响应及GET /api/v1/auth/sessions/current返回operator csrf_token；display交换响应及GET /api/v1/display-sessions/current返回receipt_csrf_token。刷新页面必须取本角色token，不借用operator token给展示端，也不因方便初始化而豁免其他已认证修改接口。

operator权限分开检查场次控制、题库编辑、题库审核、诊断/回放、评测、维护、展示票据管理；本机首次账号/角色由受控初始化与维护流程建立，首发Web不实现任意角色CRUD。返回actor_id/display_name/permissions；前端隐藏按钮仅改善体验，后端每条路由和命令都验证权限与资源归属。

一次性展示票据由operator创建，范围绑定场次、用途primary或preview、60秒兑换期。展示页从fragment取票据后立即清除地址，再POST /api/v1/display-sessions兑换；票据不能进query、日志或localStorage。交换后获得lw_display、服务端display_instance_id、render_generation、receipt_csrf_token和到期时间；operator和display会话最大默认8小时，可撤销。展示接口不能降级使用operator cookie代替display授权，也不能从display会话跳进private-state。

同一正式场次最多一个被授权的primary展示实例；其他预览实例只读，不能推进官方履约。刷新时有效cookie可GET display current，不重用已消耗fragment票据。WS resume授予新primary连接时轮换render_generation并关闭旧连接；resume_ready返回最终代次和该代次下pending_effects，之前不提交回执。旧batch不能改代次直接重发，须以新授予效果重新真实处理。撤销票据时撤销相关会话、关闭WS并使旧回执权限失效。管理员私有预览不会悄悄成为primary。DISPLAY和STUDIO的WS握手使用角色cookie与Origin验证，不把凭据放URL；原生浏览器WebSocket不依赖自定义Authorization头。display角色响应固定为display_instance_id、render_generation、session_id、purpose、receipt_csrf_token、expires_at；STUDIO使用独立GET /api/v1/studio/sessions/{session_id}/snapshot，不能拿DISPLAY游标或普通场次详情冒充原子私有快照。

## 05｜本机数据模型、约束与事务

下表字段为最低持久要求；金额/积分使用整数，分数使用有限数值和统一一位小数显示，不把NaN写入JSON。所有表带created_at/updated_at或不可变记录时间。

| 实体 | 关键字段与约束 |
|---|---|
| operators / operator_sessions | password_hash、权限集合、disabled_at、expires_at；凭据不进普通日志 |
| live_sessions | mode、app_id/room_id、status、rules/current+next版本、version；official活动场次按app/room唯一 |
| participants | session_id、平台身份的服务端映射、display_name；unique(session_id,identity_key)，昵称不是键 |
| puzzle_versions | puzzle_id/version、word、aliases、分类/难度/提示/解释、来源、审核状态；发布后不可原地改 |
| model_manifests / calibrations | 模型/tokenizer revision、维度、精度、预处理、词库与校准hash；发布题引用完整冻结组合 |
| rounds | status、epoch、version、puzzle_version、manifest、rules_version、deadline、winner_seq/participant、end_reason；活动轮按session唯一 |
| inbox_messages / guesses | 可信来源与原始ID、规范词、participant、round/epoch、admission_seq；source唯一、unique(round,participant,normalized_word) |
| score_jobs | guess_id、input_versions、deadline、lease_until、attempt/status；任务领取与结果幂等 |
| points_ledger | round/participant/reason/reference/delta/reverses_id；参与词、档位、获胜和冲销均有唯一键 |
| round_settlements | round_id主键、reason/winner、version；每轮一次正式终结 |
| outbox_events | session_id、audience、seq、event_id、immutable payload；unique(session,audience,seq) |
| display_sessions / effects | display_instance、render_generation、用途、expires；effect→delivery/source映射与可呈现反馈，不含私有答案 |
| render_receipts / ack_outbox | delivery/stage/实例/代次、实际处理时间、上报状态；每阶段幂等，processed不从落盘推定 |
| relay_deliveries / checkpoints | stream/seq、不可变原generation/epoch、hash、当前授权信息；连续persisted/admitted/terminal水位 |
| replay_jobs / import_jobs / evaluation_jobs | 模式、不可变输入、状态/版本、错误报告与取消原因；不与正式账本合并 |
| operation_audits | actor/action/resource/version/reason/request_id；脱敏可追踪 |

关键约束示意，迁移时须在真实PostgreSQL验证：

```sql
CREATE UNIQUE INDEX uq_active_official_session
ON live_sessions(app_id, room_id)
WHERE mode='official' AND status IN ('ACTIVE','ENDING','RECOVERY_REQUIRED');
CREATE UNIQUE INDEX uq_active_round
ON rounds(session_id)
WHERE status IN ('PREPARING','RUNNING','PAUSED','DRAINING','FAULTED');
CREATE UNIQUE INDEX uq_logical_guess
ON guesses(round_id, participant_id, normalized_word);
CREATE UNIQUE INDEX uq_points_reason
ON points_ledger(round_id, participant_id, reason, reference_id);
CREATE UNIQUE INDEX uq_reverse_once ON points_ledger(reverses_id)
WHERE reverses_id IS NOT NULL;
CREATE UNIQUE INDEX uq_audience_seq
ON outbox_events(session_id, audience, seq);
```

锁顺序统一session/room→round→participant/guess→ledger→event-counter，其他路径不得倒置。外部HTTP、模型推理、等待WS回执均在事务之外。版本CAS、最终状态与行锁一起检查，数据库sequence/IDENTITY只用于普通记录ID，不能用作可提交顺序或截止水位。

### 命令与异步意图

official创建轮：事务保存PREPARING及冻结版本→记录window.open意图→事务外发送中继命令→收到规范开启屏障后事务推进RUNNING并写事件。local以本节本地屏障事务代替中继开窗。失败返回pending或具体错误，不能开窗失败却在UI显示正常计分。暂停、恢复和结束同样有command_id、expected_version和可查询状态；状态未一致时显示处理中。

### 本地演练与回放的时间、入场和屏障分流

official继续使用第08节relay窗口、可信时间与关闭屏障。rehearsal完全离线：同一session事务锁内维护可提交的连续admission_seq与本地open/pause/close屏障；事务失败不消耗可见入场序号。每轮计时锚为`{boot_id,mono_started_ns,remaining_ms}`，以本版本boot单调时钟裁定入场和截止；UTC deadline仅展示。pause/close在同一有序本机入场流内冻结边界，随后按既有最多2秒评分收尾结算；不请求relay/lease、不等待5秒运输收尾，也不生成官方ACK/履约。人工输入仍经完整身份/格式/限流/去重/判胜规则。

replay使用持久`replay_cursor`、受控虚拟回放时基及记录顺序，虚拟时间仅由已认证的start/pause/resume与回放调度器推进，不能以网页时钟裁定。复用本机入场/账本规则但命名空间与正式场分离，不回发平台履约；checkpoint含虚拟时点、cursor、round/epoch、remaining和输入版本，重复恢复不重入同条记录。

跨boot旧mono值全部作废。local旧RUNNING默认INTERRUPTED后new_round；显式resume_local_round只允许持久PAUSED的remaining_ms或完整可靠checkpoint重建新boot计时锚，缺证409 `LOCAL_TIME_RECOVERY_UNSAFE`，不得用旧UTC推算剩余时间。official重启始终不得续旧RUNNING轮。此分流同时约束第06节到时/暂停/恢复；其中relay运输等待仅适用于official。

### 评分结果提交

领取任务使用短租约，保存guess_id、round_id/epoch、manifest/calibration/target版本及截止。事务外调用scorer；事务内重新锁round并检查代次、窗口、状态及幂等键。RECONNECTING只允许落盘/缓存待复核，不提交正式积分；旧轮、VOID、INTERRUPTED、过期租约或版本不符写RESULT_STALE终态。多次执行相同任务不会生成多份积分。

## 06｜输入、判胜与回合执行

本节入场与积分规则共用；时间/屏障按第05节模式分流，relay资格、运输收尾、官方履约只作用于official，local依本机/虚拟时基闭环。

正式严格输入为“猜＋本轮短码＋一个中文词”，解析先分离指令/短码，再做NFKC和首尾空白规范化。前端把后台生成的短码作为不透明文本展示，不固定长度；后端使用2–4位大写ASCII字母/数字且在活动与保留窗口内不复用，池耗尽明确阻止新轮，不能默默复用旧码。词语为2–4个Unicode汉字；不做隐式拼音/错别字/繁简替换，等价关系只来自审核别名。每条消息只取一个词；普通聊天不进入猜词流程。

顺序：来源/模式→源消息幂等→回合/epoch/短码/窗口资格→participant映射→字符/词长→用户/全局限流→同人同轮同词→精确答案/别名→非命中评分任务。拒绝返回明确status/reason，不以0分伪装错误；同词多用户可复用向量，但参与记录各自保留。

首期限流设计起点：同用户每秒1条、10秒最多5条、每轮同词一次；本机待评分队列上限200、scorer批次上限32、单词输入上限32 UTF-8字节。源码接收容量与模型容量分开，过载消息有真实终态和合规反馈，不成功接收后静默丢弃。以上为WP02/32验证后冻结的配置值，不是实测容量。

### 状态与终结

IDLE无当前轮；记录从PREPARING开始。RUNNING可暂停或进入DRAINING；PAUSED在正常人工暂停后可恢复；DRAINING完成原子结算后REVEALED→INTERMISSION→新PREPARING。依赖失败进入FAULTED或RECOVERY_REQUIRED，不能由页面自行回RUNNING。

| 事件 | 必须行为 |
|---|---|
| 精确命中 | 按连续入场顺序锁定最早winner_seq；停止接受更高序号积分；有界收尾后一次结算 |
| 相关分很高 | 最多99.9，永不solved；不使用四舍五入100或可滑动阈值判胜 |
| 到时 | 等待中继关闭屏障和close_seq以内的入场记录；5秒运输收尾缺证则中断，不宣判无人猜中 |
| 非命中待评分 | 入场资格已确认后最多2秒收尾；超时明确失败，不捏造分数 |
| 正常pause | 先取得暂停屏障；保留此前有效任务；冻结剩余时间，resume据中继确认新deadline |
| skip/void | 仅尚未原子结算的活动轮可终结VOID并冲销整轮账本；reason必填；settlement已存在则409 ROUND_CLOSED，正常结算先提交后不可被void改写 |
| 故障中断 | 终结INTERRUPTED；取消未提交任务，保留已提交参与/档位，禁止新获胜分；原子已结算的原结果不改 |
| 重启/休眠恢复 | official旧轮不无缝续接，先核对租约/屏障/游标和终态，主播确认新轮/新码 |

### 积分事务

首次有效非命中词每人每轮1分、最多5分；best_non_solved达到50/70/85三个档位各2分，按档位唯一账本补齐，最多6分；精确首位20分。顺序无关，同一组成功分数乱序返回时总档位分相同。揭晓前的每次成功反馈可提交参与/档位账本；最终结算事务锁定round、唯一settlement、最终赢家奖或VOID冲销、投影与outbox一起提交。模型任务尚未成功不发其积分。

结算前后崩溃按事务重试，不覆盖历史积分余额；VOID使用reverses_id逐笔冲销，仅限尚无settlement的活动轮；锁round后先查settlement，已存在返回409 ROUND_CLOSED，不改写已结算历史。候选赢家尚未最终结算期间若发生按规则必须中断的故障，不新增获胜分；具体中断原因和已提交参与记录保留，不能假称该轮已正常完成。

## 07｜真实模型、校准与题库发布

scorer仅提供内部POST /internal/v1/embeddings：request_id、manifest_id、texts(1–32)、deadline_ms；返回同manifest、dimension和vectors。调用通过本机引导期的内存凭据认证，不从浏览器调用、不接受远端任意模型路径。维度以manifest为准，必须固定revision、tokenizer、pooling、normalize、精度和预处理，不用模型名字符串代替版本。

```text
exact = normalize(guess) in frozen(normalized_answer + approved_aliases)
if exact: solved=true; display_score=100
else:
    raw = dot(l2(encode(guess)), frozen_target_vector)
    require finite(raw), correct dimension, nonzero norm
    scaled = 99.9 * clip((raw - b) / (u - b), 0, 1) ** gamma
    require finite(b,u,gamma), u>b, gamma>0
    display_score = min(99.9, round(scaled, 1)); solved=false
```

b/u/gamma来自固定校准样本，不从代码猜默认业务阈值；相关/无关分布重叠的坏题拒绝发布。vector缓存键为manifest/normalization/text hash；成对展示分键另带puzzle/calibration版本；缓存有条数和字节上限、同词并发合并。批次窗口初值20–50ms，CPU线程默认2且可在1–4内压测；不默认抢占OBS编码GPU。

题库草稿保存word、分类、难度1–5、审核别名、最多3阶段提示、解释、来源。CSV先生成不可变行错误报告，确认后只写明确选择的有效行；重复文件/任务按幂等键处理。发布依赖完整manifest、校准、审核决定与有限字段校验；已有已发布版本不可PATCH原地改，修改创建新版本。禁用只影响将来选题，当前轮继续冻结版本或由主播VOID。

G1-Q使用20题/约200词对方向试验，再100题/约1000词对双人标注；calibration与blind分开，blind在标注锁定前不泄机器分。后端计算真实原分、展示分、成对排序和分组指标，不能接受客户端passed=true。目标相关高于无关的排序正确率至少90%，并审查多义/反义/生造词。G1-R另在M5测Windows/OBS共机与真实独立词吞吐；Q通过不等于资源通过。模型失败正式开局不可用，mock只能用于明确标记的界面fixture。

## 08｜公网中继与本机连接的实施协议

本节仅用于official；rehearsal/replay不依赖公网可达、relay或lease，其本地屏障/恢复按第05节执行。

### 中继库与不可变投递

中继表至少包含room_owners（app_id/room_id主键）、relay_streams（连续计数）、relay_inbox（源消息唯一键）、relay_frames（不可变事件与屏障）、relay_windows（窗口版本）、relay_ack_jobs/stop_jobs（官方任务）。session_id仅是当前owner绑定场次，不进入owner唯一键。payload可包含原评论，但不持有哪词是指定答案的映射。

```text
callback(raw bytes):
    validate official signature, registered app/room, type, size
    begin relay transaction
      lock room_owner -> current_window -> stream_counter
      deduplicate (app_id, room_id, type, source_msg_id)
      now = trusted relay receive time after lock
      if open window expired: persist close barrier first
      bind original owner_generation, round_id, window_epoch, eligible
      allocate stream_seq from transactional counter
      persist raw reference + immutable frame bytes + counters
    commit
    return official success response
```

回调正文初始上限1MiB、批次最多1000条、WSS单帧最大64KiB；超大返回PAYLOAD_TOO_LARGE，不先确认再丢弃。批次内逐条保持持久序号，分帧投递。官方未知/不合格来源不通过普通Web鉴权替代验签。若批次不能原子写入，不能返回已接收；平台本身可能丢评论，保障边界从中继已确认落盘开始。

中继将包含schema、stream/seq、原owner、round/epoch、接收时间与源内容的UTF-8载荷持久序列化一次，SHA256计算原字节。传输帧携body_b64、immutable_sha256、stream_id/stream_seq、当前delivery_generation与连接身份；本机解码校验字节摘要、重复字段和Schema。重投不能重写原owner/epoch/eligible；同序号不同hash直接gap/安全故障，不覆盖本地记录。

Windows连接组件位于API的modules/connectors，独占一个当前WSS；Launcher仅托管API，不再另建一套relay消费者。原生Python WS可在握手Authorization头传设备短期令牌，禁止query token；前端浏览器不接触此令牌。每次重连更新connection_nonce并关闭旧通道，同generation不等于旧连接永远有效。

### 本机三水位与五种确认

本机收到数据/屏障后在短事务写relay_deliveries并更新连续persisted_seq，提交后才发transport.persisted。admitted_seq表示业务入场/拒绝已确定，terminal_seq表示评分/取消等业务终态已确定；二者均不表示画面已呈现或官方履约已完成。序号有缺口只缓存后续帧，不能先处理高号赢家。

1. 中继HTTP确认：源消息已在中继事务提交。
2. 本机persisted ACK：该连续区间已在本机事务提交。
3. 展示received：primary客户端实际收到绑定效果。
4. 展示processed：该客户端按认可规则实际处理并呈现效果。
5. 官方履约结果：中继调用平台接口成功或仍待重试。

每阶段有独立唯一键、时间和失败原因。ACK丢失重投只更新既有确认，不重发积分；客户端离线不能用第2步推定第4步。平台临时失败的重试仅重报履约，不重复执行游戏效果。

### 租约与窗口

所有权按(app_id,room_id)唯一，维护installation_id/lease_id/owner_generation/到期时刻。设备配对要求已认证的管理意图和可信房间核验，不能凭自报room_id取得控制权。提前撤销先关旧窗口，旧实例确认停止或其保守期限失效后才授予新可提交期；新session也不能绕过唯一owner。

心跳2000ms、重连宽限6000ms、租约15000ms、安全余量3000ms，均为待测默认值。本机按最近确认TTL减余量及单调时钟检查，每次正式结果事务前检查租约与epoch；不能只在连接建立时检查一次。中继大幅时间回退/不确定时关闭窗口并告警，不让不可靠时间延长入场资格。

PREPARING先本机落盘，再请求window.open；中继在同一房间锁内确认open_at/deadline/window_version/epoch，写开启屏障后本机才能RUNNING。中继对接收、开窗、pause/resume、截止都使用同一锁与事务计数器。

到时关闭时`close_seq`为关闭屏障之前最后一个可入场边界，关闭屏障本身有后继stream_seq。deadline后发现的新回调先关闭旧窗口，再写eligible=false的后续记录。客户端运输收尾最多5000ms并等待屏障及close_seq内连续入场；之后非命中评分再最多2000ms。缺屏障/缺序号/运输超时只能中断，不能把未知评论判成“无人猜中”。

本机在上述有界收尾内发现有效原窗口中最早正确winner_seq，仍可判SOLVED；若中继已按TIMEOUT关闭，旧expected_window_version的close请求返回原规范终态/屏障，本机校验winner_seq≤close_seq、epoch与源资格后幂等确认引用，不重开窗口，也不因409丢掉合法赢家。传输关闭TIMEOUT与业务终结SOLVED分别记录，中继不重新判答案。winner_seq之后的词不加参与或获胜分。

### 断流、重投、故障中断

WSS断开先进入RECONNECTING：冻结正式业务提交，允许继续持久接收/暂存计算结果，原倒计时不延长。6000ms内若原租约、window/epoch、连续水位仍有效，可按原relay_received_at复核短重投。达到6000ms失联、5000ms运输收尾超时、休眠/重启、租约过期或不可补齐gap才终结INTERRUPTED；未提交结果取消，已提交参与/档位保留，旧积压仅归档。已有原子结算保持原结果。

故障恢复先同步游标、owner、窗口与终态，主播确认新轮/新短码；不自动接续旧轮。不支持跨电脑无缝接管：新installation需停旧实例、恢复受控备份、重新绑定并开新场。

中继载荷初值24小时、每房间100万条或1GiB先到为准；接近配额告警，不能容量不足仍成功确认。载荷清理不回退stream计数；源ID/hash/窗口/终态去重元数据按诊断期至少30天保留。无法补齐时发送stream.gap并停止正式计分；若本机恢复点落后于云端最早保留点，明确RPO和缺口，终止旧场，不承诺云端重建本机全库。

## 09｜快照、事件与真正的展示回执

### 两种原子投影

DISPLAY和STUDIO各自拥有(session,audience)连续seq，不能过滤一个共享流后让私有事件产生公开假缺口。relay.stream_seq仅用于输入传输，不能作为浏览器游标。快照通过一致读取/锁定同一audience计数器取得状态和as_of_seq；事务提交后订阅通过持久outbox补齐窗口。

- DISPLAY快照：schema/contract、session_id、mode、run_purpose、as_of_seq、server_time、round、transport、ranking、latest_feedbacks、reveal、pending_effects。
- STUDIO快照：独立as_of_seq与server_time、public_view、private_round、session_rules、next_rules、readiness、pending_commands。它可含主播私有谜底，不能用于display cookie；普通GET场次详情不能冒充原子快照。

DISPLAY投影只给top8词榜、top3场次玩家和最多20条最新反馈；完整追踪/历史走私有分页API。pending描述/授权另受128额度约束，不将全部历史猜词塞入快照。

PublicRound使用round_id/status/version/window_epoch/short_code/category/answer_length/published_hints/clock；published_hints是`[{stage,text,revealed_at}]`而非字符串数组。运行态reveal=null；REVEALED/INTERMISSION才允许PublicReveal含答案、解释、赢家显示名和下轮时间。公共字段、日志、静态bundle均不下发aliases、target_vector、neighbors或私有题库映射。

### 恢复步骤

1. 客户端GET本角色快照，保存对应as_of_seq，不播放历史短动画；snapshot.pending_effects在恢复期只是有界描述，不授予新代次额度、不进入履约队列，也不据此上报received/processed。
2. 同角色WS握手，发送resume(after_seq)；后端按序发送delivery_mode=replay帧，恢复期只应用投影，帧中旧effects不授予额度、不入履约队列，因此catch-up不会等processed。到一致边界再发送resume_ready，给DISPLAY primary新render_generation及至多128个真正待处理的效果授权，随后进入live；STUDIO固定null/[]，preview不获履约权。heartbeat只报latest_seq和时间，不推进客户端已应用水位。
3. replay只更新绝对状态，不重播获胜动画、不重复加分。排名更新是完整投影，不是客户端累计积分delta。
4. 重复seq/event_id幂等；后继不连续或超出保留窗返回resync_required并重新取快照。不能临时把本地cursor改成server latest以掩盖缺口。
5. round.started原子替换该轮词榜/最新猜词/reveal/动画，**不清独立的未履约effect/receipt队列**。旧轮效果带origin_round_id/window_epoch，只可显示为静态历史反馈，不能改新轮排名/计时/赢家。

```json
{
  "kind":"event","schema_version":1,"contract_version":"LW-C1/1.0.0",
  "event_id":"demo_event_1042","session_id":"demo_session","round_id":"demo_round_7",
  "seq":"1042","server_time":"2026-10-25T02:00:01.000Z",
  "type":"guess.feedback","delivery_ids":["demo_delivery_1"],"delivery_mode":"live",
```

### Effects与回执持久化

效果与源消息映射在后端保存，真正未完成效果由resume_ready及live授予恢复，而不是对snapshot/replay描述直接履约。只有primary实例及当前render_generation可POST received/processed；preview不得履约。received需该连接确已接收当前代次授权的效果；processed需此前received且FE实际按认可方式处理呈现。旧代次、未知delivery、跨场次、无处理证据或超大批次拒绝并保持待完成，不把系统队列清理当作渲染完成。

反馈可按G0认可方式聚合，每个效果最多32个opaque delivery_id；合并效果仍保留全部源映射和状态。前端过载未呈现的效果不能上报processed；暂不认可聚合时应限制正式接收负载或重新确认玩法范围，而非虚假确认。播放器刷新后的旧效果可作静态“上一轮反馈恢复”，不再次播放庆祝。

恢复泵有界但不能反向阻塞握手：RESUMING的snapshot/replay只恢复投影，旧效果描述不占新代次额度、不等待回执；旧generation授权在换代时失效。resume_ready在一致边界才授予至多128个pending，其余留持久effect表。LIVE期间仅在数据库已为当前primary/generation预留额度时，事件才携可入队effects；额度满时仍可发送视觉feedbacks但effects=[]，未授权项保留在后端。只有processed释放额度，received不释放；释放后按DISPLAY顺序补送guess.feedback（feedbacks=[]、effects为历史授权批次）。授权帧一经持久化不可重写payload，重连时以replay投影处理并在新Ready重新授予。preview不取履约队列，不能靠丢弃/刷新/跳seq解锁。

本机receipt事务保存阶段及ack_outbox→中继幂等接收display阶段→relay_ack_jobs调用官方。即使官方响应丢失，也不能再次执行积分。客户端发生隐藏/卸载、断线、撤销、角色变化时，未完成效果保留并告警，不自动补齐processed。

历史共同路由清单见文末C1；当前后端以第17节组合增补新增私有能力，此处规定基线业务语义。详情表内字段均由服务端校验，不能以任意JSON对象透传到数据库/本机进程。

| rounds create/commands | 只提交session与expected_session_version、random或specific/puzzle_id选择，不提交答案/评分；pause/resume空args，skip/void reason≤200，reveal_hint stage=1/2/3 |
| 命令查询 | GET commands/{command_id}按actor/资源授权，返回pending/applied/failed/cancelled、resource_version、state与error；异步失败不能永远保持pending |
| display会话与票据 | operator发票据/撤销；一次交换与GET display current返回角色专属CSRF、实例和代次；preview/primary区别明确 |
| 连接器commands | connect/start/stop/query，目标来自已登记配置，禁止任意URL/代理脚本；返回命令状态，任务停止失败可查询 |
| 人工猜词 | 仅rehearsal，昵称为演练标记；返回accepted/reason/guess_id并经正常事件展示；不能把is_test=false变official |
| replay | 上传已授权脱敏记录，创建独立replay场次；start/pause/resume/cancel带expected_version；结果含replay_session_id、事件总量/完成/拒绝数和cursor，不写正式场账本 |
| puzzle搜索/草稿 | cursor分页、分类/难度/状态筛选；word为Han2–4，aliases同口径，提示≤3阶段/每条≤120、解释≤500、来源≤500；PATCH只修改草稿或创建新版本 |
| puzzle commands | evaluate绑定manifest；approve绑定evaluation_id与approve/reject/notes≤500；publish绑定approved_version；disable带reason；都检查expected_version与权限，不接受客户端pass布尔 |
| CSV导入 | multipart UTF-8/可选BOM，初始2MiB/10000行；创建validation job，GET含行号、字段/错误码、有效/无效数量与预览；confirm_valid_rows/cancel显式执行，返回新草稿ID集合，不自动发布 |
| scoring evaluation | puzzle_version_id、manifest_id、split=explore/calibration/blind和pairs[{guess,human_rating}]；blind必须完整标注后一次提交并冻结输入hash；GET在锁定前不返回机器分 |
| messages与trace | GET messages按场次、状态、原因、cursor分页（默认50、最多100）；summary含内部message_id/round/source_mode/status/reason/receive time/规范词/安全昵称；trace返回各阶段时间与终态，不默认暴露平台UID/凭证 |
| analytics | 保留原聚合字段，精确指标分母、封账、未终态任务、分钟/轮明细、稳定分页及同快照CSV以第17.3节为准；不虚构观看/停留分母 |
| runtime | status固定C1字段；commands仅stop或request_maintenance的五类operation，请求不等于执行；原生确认/UAC/路径归属按第12节，不接受任意path/executable/URL |

业务修改带Idempotency-Key和expected_version；长任务返回统一JobResult：job_id/status/version/progress{done,total}/result/error。result按任务类型固定Schema：导入为行报告，回放为事件计数，评测为manifest/puzzle/标注锁定/分组指标/词对原分展示分和calibration_id。不得用一个无类型object要求FE猜字段；WP03应从本表和C1生成实际JSON Schema及TS。

命令响应统一`{command_id,status,resource_version,state,error}`，status为pending/applied/failed/cancelled，error在成功/处理中为null。初次处理中202，已应用200；GET查询成功响应200但command.status可failed。重复相同key返回同一command的现有状态，不再次执行。资源版本冲突409并返回可重取资源信息，不自动重放有破坏性的操作。

HTTP基线错误使用C1固定映射（第17节新增私有错误的明确HTTP映射另计）：401身份失效、403权限/展示授权、409版本/租约/窗口/缺口/旧结果、413过大、422字段错误、429限流、503依赖或模型未就绪。retryable只用于幂等安全的网络/暂态失败，不能让前端自动重试VOID、切场或升级；明确失败仍允许用户新意图与新key重新发起。

## 12｜Windows原生运行与交付实施契约

本片段是工程实施规范，产品根记为 `R`；本文只定义文件、接口与验收，不证明当前工程实现状态。共享契约固定 `LW-C1/1.0.0`、`schema_version=1`；launcher状态、公有API与超时沿用该历史基线；readiness和新增私有能力以第17节组合契约为准。本地进程退出码不新增共享HTTP错误码。目标为仍在支持期的Windows 11 x64，Python 3.12、CPU PyTorch、单API、单scorer、PostgreSQL 16专用服务。ARM/32位/旧系统未列入首发支持范围。

### 12.1 模块与发行清单

`R/apps/windows-launcher` 对外提供原生状态窗口/托盘入口及本机控制适配器，内部包含状态控制器、Windows进程宿主、身份健康客户端、凭据引导、维护执行器；中继连接由API的modules/connectors独占，Launcher不另建WSS消费者。首版基线采用Win32原生消息循环、状态窗口与通知区域，由Python ctypes封装，业务页面仍使用React；不引入Qt/Tk/WebView2作为运行前置。最小本机窗口须在API启动前显示阶段、失败原因、日志位置与重试/退出入口。UI直接订阅本机控制器，不能依赖React/API才能报启动错误；原生窗口初始化失败时以系统错误框和脱敏日志报告。WebView2仅为可选增强，不是运行依赖。

发行使用Windows x64原生CI构建PyInstaller onedir，API/scorer/launcher为角色明确的独立入口，不把当前冻结EXE当Python解释器运行 `-m`。锁定wheel、依赖与打包工具，CI拒绝运行期pip安装、在线模型补齐和来源不明二进制。签名产物与最终摘要一并保存；两次构建应可核对同依赖与输入，不能据此承诺签名PE逐字节一致。onefile/Nuitka须另做等价验证，首版不切换。[PyInstaller平台与打包边界](https://pyinstaller.org/en/stable/)、[冻结多进程](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html)

### 12.2 PG专用服务与首次授权

程序/迁移脚本放Program Files专属版本目录；模型放ProgramData专属只读版本目录；PG数据单独放ProgramData，仅专用低权限服务账号、SYSTEM与管理员可访问；当前用户配置、日志、DPAPI密文放LocalAppData。通过Known Folders定位路径。安装器拒绝路径越界、可写可执行目录及未经核对的重解析点，并设置显式ACL，不能假定ProgramData天然私有。

安装器建立专用非交互本地服务账号和“作为服务登录”权限，由SCM安全存储服务身份，不在命令行传账号密码。服务配置只能管理员修改。数据库使用SCRAM认证、仅回环监听，运行角色只有业务所需权限；迁移角色与引导管理员仅供受限维护通道使用。服务名、端口、二进制路径、PG系统标识、数据目录及本产品实例标记共同判定归属；发现已有服务/端口/目录冲突即停止该安装步骤或明确选择新配置，绝不接管、停止或升级别人的PG。服务随系统独立运行，不归launcher Job。[pg_ctl服务能力](https://www.postgresql.org/docs/16/app-pg-ctl.html)、[Windows服务权限](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights)

跨管理员引导顺序必须可恢复：

1. 未提权入口记录当前交互用户SID与安装事务ID，并启动仍属于该SID的伴随进程；另一管理员仅执行UAC维护任务，不能把该管理员SID误作主播。
2. 维护组件建立专用PG、schema与运行角色后，通过一次性本机命名管道交付运行凭据。DACL只允许目标SID及维护身份，拒绝远端客户端；核对对端PID、进程令牌SID、安装事务和随机挑战。管道名不是凭证，客户端自报SID不作为证明。
3. 伴随进程收到后立即用当前用户DPAPI保护、原子写入LocalAppData，再返回不含密钥的保存确认；维护端随后清零内存缓冲和引导材料，完成实例登记。运行用户不得获取迁移角色凭据。
4. 管道身份不符、目标用户退出、DPAPI失败、确认丢失、事务取消或双方管道已就绪后超出30000ms的一次性引导预算（不计UAC输入和组件安装等待），均不标记安装完成；进入安装修复。重试先核对实例，再轮换未确认的运行凭据并重新引导，不复用旧一次性交付、不新建第二个实例、不启用trust或落明文文件。

初装中断保留带事务归属的资源供修复，仅清理已确认由本事务建立且无业务数据的临时资源。用户级DPAPI通常绑定用户/机器，跨用户/跨机恢复重新授权；机器级DPAPI也不能替代密文ACL。[DPAPI约束](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

### 12.3 私有引导与进程身份

launcher先取得实例级命名互斥锁；锁DACL限目标SID及维护身份，第二次启动验证现有控制端后只唤起窗口。端口占用不能证明已有本产品进程，禁止按端口杀未知程序或自动信任HTTP健康页。

launcher创建API/scorer时采用显式路径、受限句柄继承清单、先挂起创建→加入Job→恢复运行；使用 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，不允许breakaway，launcher不向子进程继承Job句柄。PG服务与已有OBS不加入Job。引导期以受限继承句柄/本机管道传入每次启动密钥，命令行仅可含非秘密句柄编号；不使用命令行、环境变量或磁盘明文传密钥。双方核对OS取得的PID/令牌SID、installation_id、boot_id、角色、发行摘要与随机挑战，再绑定实际监听端点；失败停止自有子进程并报身份错误。[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

API内部控制管道只接受固定 `status/stop/maintenance` 及状态通知，不接受任意进程、路径、shell或下载URL；此管道不是新增HTTP路由。scorer仅暴露 `/internal/v1/embeddings`，API使用本版本启动密钥对请求ID、正文摘要和manifest摘要做HMAC；scorer校验签名、请求ID重放及固定模型后才处理，响应也签署请求ID、模型清单及结果摘要，API核验后才接纳向量。密钥轮换随boot变化，不能用可公开读取的installation_id代替认证。

共享HTTP保持原路由：`GET /api/v1/health/live`只给最小存活信息；`GET /api/v1/health/ready`、`GET /api/v1/runtime/status`是operator私有接口；`POST /api/v1/runtime/commands`沿用operator cookie、Origin/Host、CSRF和Idempotency-Key，采用共享command请求/响应形状。command只允许`stop|request_maintenance`，args为`{reason,operation?}`；operation仅`backup_local|verify_local_backup|restore_new_instance|upgrade_app|switch_model`。不得绕过活跃场次停止契约。本机启动前的status通过上述管道获得同形readiness，不降低HTTP鉴权来方便launcher。

`runtime/status`保留C1基线字段`{version,launcher_state,active_session_id,installation_id,app_version,model_manifest_id,schema_version,readiness,backup_status,maintenance_status}`；boot_id、component_versions、last_exit只保留在本机IPC与日志；第17节仅向其私有readiness子模型追加明确扩展字段。readiness保持`checks={db,model,wordbank,relay,lease,display}`、`gates={G0,G1_Q,G1_R,G2,rc_verified}`、三个can_*布尔值；每项只能为pass/fail/pending/not_applicable，并含reason_code/message。launcher展示后端计算结果，不自行把进程存活改成pass。

维护HTTP只提交请求，成功响应`pending`不代表完成维护。原生窗口向目标用户显示operation、已核验发行/模型摘要、备份时间/数据损失边界及目的实例，必须本机确认；需要服务/受保护目录操作时再发起UAC。确认绑定command_id、目标实例、规范路径及制品摘要，执行前重新核对，防止确认后替换文件；同幂等请求只返回原任务，不重复弹UAC。路径由原生文件选择器或已登记实例生成，不接收Web传来的任意path/executable/URL。维护端重新规范化路径、核对允许根/实例归属与重解析点，拒绝用户可写脚本被提权执行；仅执行签名发行包内的固定维护动作。跨机备份可由原生用户选择，但按不可信文件校验、先独立恢复，不直接覆盖现库；取消确认返回明确取消结果，不把HTTP请求转成静默执行。

Uvicorn固定asyncio、一个worker、无reload；所有入口置于main保护，使用multiprocessing时最早执行freeze_support；禁止import时启动子进程或模型。scorer为独立HTTP进程，API中不重复加载模型。[Uvicorn Windows设置](https://uvicorn.dev/settings/)

### 12.4 状态、预算与退出码

| 状态迁移 | 守卫与结果 |
|---|---|
| STOPPED→CHECKING | 用户启动；锁、实例身份、manifest/签名/ACL、凭据检查通过后继续；不兼容schema转MAINTENANCE |
| CHECKING→DB_READY | 专用PG身份/连接/schema/运行角色验证通过；服务未运行显示修复，不由普通用户循环提权启服务 |
| DB_READY→STARTING | 建Job并启动自有进程；API在api_start_timeout=30000ms内完成私有挑战与业务初始化，否则FAULTED |
| STARTING→WARMING | API已被证实身份且schema匹配；scorer从本地加载、校验、预热，model_warmup_timeout=120000ms |
| WARMING→READY_REHEARSAL | API/DB/model/基础wordbank与实例身份可用且无待恢复阻塞；开放登录、CREATED建场、展示绑定与连接准备，不要求具体场次can_rehearse或primary已绑定 |
| READY_REHEARSAL→READY_OFFICIAL | 正式模式运行检查通过且can_test_live或can_go_live成立；两者仍分别控制试播与正式开播，原生/网页均显式标测试或正式，状态名不授权越过G2/RC |
| 任一运行态→RECOVERY_REQUIRED | 存在未结束轮/持久任务，或正式链路达到故障中断判据、睡眠、重启/身份代次变化；关闭正式输入，恢复契约完成前不自动降为可演练 |
| RECOVERY_REQUIRED→CHECKING | 仅显式恢复/重试；先核对旧场与relay，不自动创建新场；恢复出的轮仍需主播确认 |
| 任一启动态→FAULTED | 无活动场次的配置、签名、身份、模型或初始化失败；保留脱敏原因，显式重试才回CHECKING |
| FAULTED→CHECKING | 用户显式重试且不存在未处理旧场；若发现旧场，改进RECOVERY_REQUIRED；只有瞬时启动错误允许按下述有限退避自动回CHECKING |
| 已清空场次的STOPPED→MAINTENANCE | 授权维护；备份/迁移/升级完成后返回CHECKING，失败留MAINTENANCE或FAULTED，不放行开局 |
| READY_*/RECOVERY_REQUIRED/FAULTED→STOPPING→STOPPED | 先走业务停止/归档与平台任务契约，再排空自有进程；shutdown_drain=15000ms到期后终止自有Job，保留未确认停止记录 |

原生窗口与API在WARMING期间即可显示准备/诊断；READY_REHEARSAL表示准备入口可用，can_*仅表示某一具体场次可以start，无场次时可以全false。READY_OFFICIAL同样不能跳过具体场次start守卫。

正式窗口/租约继续复用C1基线：heartbeat_interval=2000、relay_disconnect_grace=6000、lease_ttl=15000、lease_safety_margin=3000、transport_drain=5000、score_drain=2000、clock_uncertainty_limit=500（均ms）；停止的各段不得额外叠加无界等待。STOPPED只表示本机进程停止，平台stop_job未确认时必须另示“停止待确认”。休眠/时钟变更处理遵循relay契约，不让本机时间延长正式轮次。

本地launcher退出码：0正常退出/已转交现有实例；10清单或兼容性错误；11实例/端口归属错误；12凭据或私有引导失败；13数据库不可用；14API启动失败；15模型校验/预热失败；16维护失败；17排空超时强制结束Job。日志另存子进程原始退出码，不能把Uvicorn的退出码误当产品码。失败不自动删除数据或重建数据库。

仅无待恢复场次的瞬时启动失败可自动重试：首次失败后最多3次自动重试，等待依次使用C1的`restart_policy.retry_delays_ms=[1000,2000,4000]`，每次重试失败递增restart_failure_count，达到`restart_policy.max_retries=3`即FAULTED；原始首次启动不计入自动重试失败数。每次先清理自有Job并重新验证实例身份。权限、缺文件、摘要/版本/凭据错误立即失败，不重试；正式运行后崩溃只进RECOVERY_REQUIRED，不以退避复活回合。显式重试建立新boot并清零启动重试计数，但不清除旧场恢复要求。这是Spec对v1.1初步退避计数的明确细化，全部预算为待测默认值，WP03核验后冻结，修改须同步共享契约。

### 12.5 模型与维护流程

model manifest包含模型仓库/revision、许可证、全部文件相对路径/大小/SHA256、嵌入维度/归一化、固定预热样本及期望有限值、校准/词库版本。完整目录须有权重、tokenizer、config和所需模块配置；拒绝越界路径、缺文件与摘要不符。scorer用绝对路径及local_files_only加载，启动期明确device=cpu；加载一次后批量编码，预热失败返回模型失败而非mock分。

CPU线程起始设计值2、调优范围1–4，不自动选择OBS编码GPU；变化进入新评分清单，不在活动轮热换。记录模型RSS/冷启动/冷缓存延迟、独立词比例、batch、缓存命中和队列水位。真实OBS画布/编码下测10个新独立词/秒30分钟、100事件/秒突发10秒与30fps目标，并记录CPU/RAM/GPU/编码和渲染丢帧；均为待验目标，不能以CI虚拟机代替目标机。[OBS资源竞争](https://obsproject.com/kb/encoding-performance-troubleshooting)

升级仅停播维护执行：验签/摘要/空间→关闭场次并排空→生成custom格式dump、角色重建信息和配置/评分清单→独立恢复验证→新版本目录→前向迁移→模型预热/兼容自检→原子切换活动版本指针。维护任务持久记录每阶段，崩溃重入先检查实际版本与迁移账本，不盲目重跑或回删数据。迁移失败不得启动旧版继续写不兼容schema。

WP31至少使用两代实际应用/schema，分别验证“旧应用声明可读写则回切”和“不兼容则从备份恢复到新实例后受控切换”；后者须明确备份后数据损失并取得恢复选择，不直接覆盖现库。模型/校准/词库作为一组切换；数据库大版本升级另立流程。卸载只移除归属核实的服务和程序，默认保留数据、备份、模型/配置并显示位置；跨机恢复DPAPI需重绑，旧备份超出relay保留窗按gap处理，不承诺云端重建业务库。[pg_dump与恢复](https://www.postgresql.org/docs/16/app-pgdump.html)

自有安装器、平台认可EXE包体、完整8页Alpha、RC是四类产物：WP20基础安装Alpha不宣称8页齐全；WP21重建全页Alpha；WP29打包平台入口并验证真实启动参数，短期token只在安全内存通道使用；WP34统一冻结安装器/平台包/API/scorer/web/relay/schema/model等摘要。平台EXE入口不能据可启动自有安装器而标为审核通过。

## 14｜观测、数据隔离与维护边界

所有输入携message_id/round_id、源模式、可信run_purpose、不可变原generation/epoch、stream_seq与各阶段时间。request_id贯穿API、任务、模型、事件和回执；日志不打印密码、票据、平台token、启动密钥、未揭晓答案或完整私密载荷。详细原始源数据只在受控持久层并按权限保留，普通trace不把源UID当公开用户标识。

生产指标只统计服务端核验的official+production、非provider测试数据、实际有效接收处理的记录；test_live、manual/replay/bridge和平台测试来源分别分栏。客户端提交is_test不具有可信性。两类模式的账本按场次隔离，回放复用源ID时使用独立命名空间，不污染正式source唯一键。

原始本机评论设计保留7天、脱敏轨迹30天、场次聚合90天；中继载荷24小时及配额、去重元数据30天按第08节执行。清理先确认引用关系，不能因载荷到期删除仍需的幂等/终态/ACK元数据。备份保留和删除必须与运营策略一致，不能把清理“unused”当授权删除业务数据。

必须分别观测：relay响应/持久失败/配额、WSS RTT/重投/gap、local入场/拒绝/排队、模型冷/热与独立词延迟、账本/事件一致性、DISPLAY渲染确认、官方履约/停任务重试。没有平台总评论分母就不报告零漏词；没有观看来源就不报告留存或流量增长。

验收目标继承v1.1：relay持久响应p95≤300ms/p99≤1s，受理到端侧反馈p95≤1.5s，10新独立词/秒持续30分钟、100输入事件/秒突发10秒，目标画布30fps。P-W额外记录relay→Windows网络及OBS编码/渲染丢帧；这些均为待测目标，不是本Spec提供的运行结果。容量未达标先限流/批处理/热点缓存/资源调整，不能无界积压或给假分。

中继通过获授权的云控制台/CI/CD部署与维护，不执行服务器SSH。本机没有公网上行控制壳，中继不支持远程shell、任意程序/路径或任意下载。数据库/模型/平台凭证有各自最小权限；安装器仅管理本产品资源，用户已有PG和OBS不受Job和卸载控制。

### 17.2 readiness：四条放行路径及可信授权

#### 状态与上下文

Beta对未测R/RC/G2允许pending，但任何已知fail不得改标pending漂白；已知安全/资源/真实链路失败须先离线修复、生成新候选并重新受控授权重测。

每项状态严格为：`pass`=本上下文有有效且匹配的成功证据；`fail`=已知失败/被撤销/不匹配；`pending`=适用但尚无完整结果或已过期待重验；`not_applicable`=该profile明确不要求此项。只有`pass`满足必需门槛，不能将pending/not_applicable按真值处理；可选项即使pass也不能补偿必需项失败。聚合gates保留真实状态，profile中另给要求矩阵，不能为方便把未测G1_R改成not_applicable。

`context={session_id:string|null,mode,run_purpose,live_profile:beta|g2_evidence|production|null,app_id:string|null,room_binding_id:string|null,installation_id,candidate_digest,model_manifest_id,wordbank_manifest_id,calibration_id,evaluated_at,authorization_id:string|null}`。candidate_digest为服务端核对实际安装/运行组件后计算的成套清单摘要（API/scorer/relay/协议/平台包体/Windows发行与模型/题库/校准），不是浏览器声称的版本。Beta同样固定一份候选摘要，不能用“未冻结RC”表达任意二进制。启动就绪仅指基础API/DB/model/wordbank/身份可用且无恢复阻塞，WARMING可进入READY_REHEARSAL并开放准备入口，不以primary或can_*为守卫。无场次上下文只提供启动检查，各profile allowed=false/reason=SESSION_CONTEXT_REQUIRED、can_*全false；GET可带session_id按资源权限求值，不持有租约、不绑定display、不写入业务状态。

`profiles={local:{allowed,blockers},beta:{allowed,blockers},g2_evidence:{allowed,blockers},production:{allowed,blockers}}`；blockers为有序数组`{item,status,reason_code}`，依checks→gates→authorization顺序列出所有不满足项。`can_rehearse=local.allowed`，`can_test_live=本场次绑定的beta或g2_evidence.allowed`，`can_go_live=production.allowed`；用途不匹配的布尔为false，不能跨场借用ready结果。GET结果只是诊断，create/start/开下一轮仍重新服务端核验。

| profile / 固定mode+purpose | 必须pass的checks | 必须pass的gates | 服务端专项授权 | 可以尚未完成的gate |
|---|---|---|---|---|
| local；rehearsal/replay＋local | db、model、wordbank、display | 无 | 当前operator资源权限；无平台live授权 | G0/Q/R/RC/G2都不参与；relay/lease对local为not_applicable |
| beta；official＋test_live（M4受控Beta） | db、model、wordbank、relay、lease、display全部 | G0、G1_Q | 有效`controlled_beta` grant | G1_R、rc_verified、G2可pending/未完成；已知fail先修复换候选重测，不产生production权限 |
| g2_evidence；official＋test_live（WP35固定RC采证） | 六项全部 | G0、G1_Q、G1_R、rc_verified | 有效`g2_capture` grant | 仅G2允许pending；G2失败后先修复/重新采证授权，不能把已知失败绕成pending |
| production；official＋production | 六项全部 | G0、G1_Q、G1_R、rc_verified、G2全部 | 有效`production_release` grant | 无 |

checks含义：db=本产品PG实例/运行角色/迁移兼容可用；model=冻结manifest真实离线加载/预热且内部身份有效；wordbank=至少一题符合当前规则、已发布且模型/校准匹配；relay=核实身份的当前官方链路与必要时间可信；lease=在CREATED准备期以同一专项授权取得、当前app/room/installation绑定且有安全余量的owner（该lease不开放输入窗、不允许计分）；display=该场次经服务端授权的primary当前连接已完成resume_ready且代次有效（local也需本场次primary；preview不满足）。组件测试可单独测这些能力，但不创建官方门禁通过证据。

G0证据固定平台app、房间能力/类别/反馈与包体入口协议版本；G1_Q固定真实模型/词库/校准组合；G1_R固定目标Windows/OBS资源配置和候选摘要；rc_verified固定WP34 RC编号/成套摘要与47项前置验收/G1复验；G2固定同一RC/房间/安装实例的WP35真实多用户/渲染/履约证据。复用较早G0/Q证据时必须在候选清单声明适用版本并验证相同内容摘要；没有明确兼容证据不得推定继承。WP31–33预候选故障/资源组件验证不依赖未来RC；WP34先冻结RC再复验；WP35无需G2先pass即可采G2。M4 beta不等待G1_R/RC/G2，消除两种循环。

#### 授权来源、生命周期和执行点

授权不是浏览器字段、operator的session.control或本机env开关。平台账号/测试资源授权与本产品放行授权必须同时有效。项目指定发布/测试负责人通过受控签名证据包签发grant；验签公钥由原生受限初始化/维护流程固定，Web不得设置签发公钥或上传自签结果。API从受限本机通道接收已验签、可追溯的证据/撤销清单并校验；relay对app/room/设备绑定再核平台授权。没有可信签发者配置时只允许local，不能自举成授权者。官方准备顺序固定为CREATED→primary resume_ready→通过连接器固定connect/start准备操作申请带授权lease→readiness→start/首轮；准备期无游戏输入窗，平台收到数据不得据此计分。local的relay/lease为not_applicable，使用第05节本地时序。

持久 `readiness_evidence` 记录 gate/evidence_id、issuer、scope、component摘要、result、evaluated_at/expires_at、签名摘要与撤销版本；`live_authorizations`记录authorization_id、kind、app/room_binding、installation_id、candidate_digest、允许profile、not_before/expires_at、max_session_duration_ms、revoked_at、签名摘要。Beta/g2 grant最长24小时，production grant最长30天，均禁止无限期。证据和grant必须具有明确expires_at，服务器验证not_before与当前服务端时间；运行截止采用以下单调保守锚，不依本机UTC延长。

签发包为`{key_id,domain:"wordheat-live.readiness",type:gate_evidence|live_grant|revocation|freshness_proof,version:1,payload,signature}`。签名输入是去掉signature后的完整对象经[RFC8785 JCS](https://www.rfc-editor.org/rfc/rfc8785) canonical UTF-8字节；算法固定[RFC8032 Ed25519](https://www.rfc-editor.org/rfc/rfc8032)，signature为64字节签名的无填充base64url。key_id映射受限信任库中32字节Ed25519公钥及允许domain/type；拒绝未知key、重复JSON键、非规范数值、未知type/version、降级与scope不符。payload含唯一object_id、issuer_id和严格递增issuer_revision；相同ID相同摘要为幂等导入，同ID不同内容或倒退revision拒绝。私钥仅在签发环境；原生受控maintenance内固定“导入已签名证据/受信key包”用例由本机明确选择及权限确认执行，key轮换包须由已有可信根签名，新安装信任根仅受控初始化固定。它是内部原生维护能力，不加入Web runtime operation，不接受Web任意路径/key或远程执行。使用成熟密码库，不自写算法，库版本由WP04锁定。

relay新鲜性证明payload固定`authorization_id,candidate_digest,installation_id,boot_id,connection_nonce,request_nonce,revocation_revision,server_time,ttl_ms`，ttl_ms在1..60000；API只接受本版本boot/连接发出的未消费挑战request_nonce，校验所有绑定、签名、撤销revision不倒退，消费nonce后拒绝重放。请求发出时保存mono_sent；响应以服务端server_time计算grant/各必需证据到期的剩余时长。运行期有效mono_deadline=min(mono_sent+ttl_ms,mono_sent+grant_remaining,mono_sent+evidence_remaining,session_mono_start+max_session_duration_ms,lease_mono_safe_deadline)，剩余<=0拒绝；证据剩余取所有必需证据最小值。准备期尚未起算场次时长，不纳入session时长项，其他grant、证据、TTL及lease期限照常生效。首次start成功事务一次性固定并保存session_mono_start，该事务以拟固定锚重算期限后提交；续期、pause/resume、reconnect及幂等重试不得重置此锚。无有效lease或可信时间锚时相应readiness为pending且禁止start，create仍允许；跨boot按既定累计时长恢复规则处理。lease安全期限仍按C1 TTL与安全余量计算。server_time的可信度/时间不确定性按C1校验，不能仅因签名正确就接受矛盾时钟。响应迟到已经用尽预算不能续命；本机UTC回拨/前拨不改变mono_deadline。跨boot丢弃全部锚和nonce，重新挑战且保守恢复session累计时长，无法证明剩余预算则结束旧场。

运行期最多每1秒检查一次期限/撤销/摘要；每个正式评分/结算结果事务提交前以及开窗前还须独立重验当前授权revision和mono_deadline，边界处不得凭旧ready快照放行。证明断更、到期、撤销、时钟不可信立即停止新输入与正式结果提交，按既有RECONNECTING→INTERRUPTED有界退出（显式撤销可直接INTERRUPTED），禁止新增获胜；已完成原子结算不改。迟到或撤销revision倒退的证明不能复活旧轮。

- create只检查身份/资源归属、用途/profile合法、grant范围与平台绑定，不要求display、lease或全部checks通过；保存mode/purpose/profile/authorization_id/candidate_digest/installation_id不可变。`live_profile`新增为create字段：test_live必填beta或g2_evidence，production固定production，local固定null。授权过期后可保留草稿但不能start；换授权须结束旧场并新建，不热换用途/profile。
- start先按第17.1节认证与幂等顺序处理，再在最新session.version CAS及锁定session/room下重验上述矩阵、授权与版本，持久化命令/授权版本和有效期；平台开窗前relay也核验同一授权绑定。异步依赖变化让命令failed并关闭已开窗口，不能先RUNNING再补证据。
- 每个新轮/恢复/租约续期重验；运行期持续检查授权到期/撤销及运行摘要。授权失效、房间/安装实例/摘要更换、必需gate被撤销或证据过期，立即停止接纳新输入，按既有屏障/INTERRUPTED规则收尾，禁止新获胜奖；已原子结算结果保持原规则。服务重启不能续用未核实的旧授权。未参与该profile的pending gate不会中断Beta。
- 版本/模型/题库/校准、relay或平台包体任一摘要变化，旧grant不匹配并失效；受影响gate先pending待复验，明确失败保持fail；G2不跨RC继承。房间重绑/installation恢复到新实例必须重新授权；不能复制grant文件获得权限。发布负责人可提前撤销，API/relay拒绝旧撤销版本和重放包。

| 失败码 | HTTP / 触发 |
|---|---|
| LIVE_AUTHORIZATION_REQUIRED / LIVE_AUTHORIZATION_INVALID | 403；缺专项grant或验签/用途/平台scope不符 |
| LIVE_AUTHORIZATION_EXPIRED / LIVE_AUTHORIZATION_REVOKED | 403；到期/撤销；运行期为持久中断原因 |
| CANDIDATE_MISMATCH | 409；运行摘要与grant/证据不符 |
| READINESS_NOT_MET | 409；必需项非pass，details含profile/blockers |
| LIVE_PROFILE_MISMATCH | 409；create/start目的或profile与不可变绑定不符 |

验收反例BE-A14（关联WT13/24、WP27/34/35）：①六checks+G0/Q pass、R/RC/G2 pending、有beta grant→仅beta可start；改production返回LIVE_PROFILE_MISMATCH，不能产生正式统计。②相同状态改g2 profile→READINESS_NOT_MET；R/RC pass且g2 grant、G2 pending→允许采证。③G2 pass但grant缺失→403。④创建前无primary/lease仍可建草稿，start返回完整blockers。⑤快照ready后撤销grant或换candidate，再start/下一轮均拒绝；运行轮按中断处置。⑥mock/组件fixture结果不能导入为gate pass。以上是待实现断言，不是实测通过。

### 17.3 Analytics：权威、可冻结、可分页的单一统计快照

权限固定为`diagnostics.read`＋场次归属；DISPLAY、preview及只有题库权限者403。统计仅本机持久记录可证明的事实，relay未知/未送达量不默认为0。所有指标先按本场不可变mode/run_purpose/profile及可信source_mode/provider_test分区；production聚合只纳入official+production且source=official、provider_test=false，未知来源进入excluded_unknown，不混入production。test_live即使真实用户也单列；replay/manual/bridge分别列，不合并成增长。场次查询不能跨场拼分母。

#### 快照字段与一致性

原GET `/api/v1/live-sessions/{session_id}/analytics` 首次不带snapshot_id时，用本机PG一致读事务生成并持久化不可变统计快照和有序轮/分钟行；返回200聚合。GET只派生可清理的只读查询快照，不改变场次、选择或封账业务状态。其响应在原有Analytics平字段外追加：

```text

context:{session_id,mode,run_purpose,live_profile,candidate_digest},
as_of:{captured_at:timestamp,local_commit_watermark:decimal-string,studio_as_of_seq:decimal-string},
coverage:{started_at:timestamp|null,ended_at:timestamp|null,through_at:timestamp,
          relay_coverage:complete|partial|unknown,relay_confirmed_stream_seq:decimal-string|null},

         local_nonterminal:{admission:int,score_jobs:int,commands:int},
         local_delivery_pending:{outbox:int,display_effects:int,ack_outbox:int},
         remote_fulfillment_pending:int|null,unresolved_gap:boolean},

              normal_completed_rounds:int,guess_attempts:int,invalid_attempts:int,

```

captured_at是数据库快照时点。每session保存事务性`analytics_commit_counter`行；影响任何返回字段的admission/guess/job/round/ledger/冲销/hint/command、outbox/effects/ACK/履约观测及待办状态事务，在统一业务锁序末端取该行锁并加1，持锁到commit。回滚同时撤销加1，等待者只有前一事务提交后才能推进，因此水位反映这些事务的提交顺序；不得用sequence/IDENTITY或STUDIO seq替代。多session事务按稳定session_id取计数器锁，取到后禁止反向取业务锁/IO。外部状态只能经可信观测落本机事务后进入快照，不查询远端拼接。快照在同一PG一致读事务读取counter及事实，得到同一个local_commit_watermark。各计数、原有平字段、分钟行、轮行均来自该次一致读；请求期间新分数/VOID/回执不得混入旧快照。计数非负整数；比率为[0,1]有限数；延迟/时长为非负毫秒。未开始场次started_at=null、through_at=captured_at且分钟items=[]。

session ACTIVE/CREATED为open；已停止接纳且仍有统计相关本机admission/score_jobs/commands非终态或恢复动作待处理的unresolved_gap为draining；只有ENDED、各轮已终态、上述统计相关本机任务全终态并已提交、时延观测已落盘或确定missing、无待执行恢复动作时才能sealed。封账由终结事务/恢复用例判定并保存，不由GET或浏览器触发。unresolved_gap=true专指尚待恢复动作裁定的缺口；INTERRUPTED经恢复用例确认不可补齐后将缺口持久终态化为archived_unrecoverable_gap、coverage=partial/unknown，unresolved_gap=false，不伪造连续完整水位；本地任务已终态即可封本机统计，不能声称relay全覆盖。投递/展示/官方履约待办单独如实返回，不阻塞仅针对本机账本指标的封账，也不被sealed隐去；远端未知返回null。final=state==sealed；sealed后的业务聚合被冻结，迟到旧帧/旧任务只进入独立归档，不更新source_mode_counts、分钟、轮或账本等已封账业务聚合。VOID仅可能在未结算活动轮发生并在封账前纳入统计；settlement已存在即ROUND_CLOSED，不存在结算后VOID修订分支。封账后迟到时延样本也只归档，不将已确定missing偷偷补入冻结指标。投递/履约诊断可以继续保存独立观测，不能借此改写已封账业务口径；旧snapshot始终不可变。

快照有效期最长captured_at+24小时（含CSV下载），后续请求需同时验证snapshot归属与当前读取权限，撤权立即403。到期410 `ANALYTICS_SNAPSHOT_UNAVAILABLE`（reason=EXPIRED）并要求重新取首屏，绝不静默生成新快照续页。seal不是无限期保存原始评论的授权；不含评论、UID、答案的最终分钟/轮聚合与场次聚合保留90天，可据其生成后续快照/CSV。仅查询物化副本最长24小时，原评论7天、脱敏轨迹30天等既有策略不变，不因快照延长。90天内重建的快照仍须保留原metric版本、水位、closure和coverage，不假装重新具备已清理的原始细节。

#### 指标口径（原有字段保持名称）

有效猜词单元定义为已入场且成功评分或精确命中的唯一`(round_id,participant_id,normalized_word)`；精确赢家计入一个单元。重复源重投/同人同轮同词/限流/格式错/旧轮/系统失败/未终态任务不计入有效猜词。VOID轮所有有效单元和积分被冲销，默认聚合不计；INTERRUPTED只保留实际成功提交的有效单元，未完成任务不计。参与者按有效单元中的session内身份去重，昵称变化不增人，同昵称不同身份各计。

| 字段 | 分子、分母/取样；无数据 |
|---|---|
| participants_count / valid_distinct_guesses | 上述有效参与者数/单元数，空集均0；“独立”不等于全场不同文字数 |
| guesses_per_participant | valid_distinct_guesses / participants_count；分母0为null |
| round_completion_rate | 正常完成SOLVED或TIMEOUT轮 / 全部终态非VOID轮（正常完成＋INTERRUPTED）；活动/PREPARING轮不进分母；分母0为null |
| median_round_duration_ms | 正常完成轮在RUNNING接受输入的累计时长中位数，排除PAUSED、PREPARING、DRAINING与轮间；VOID/INTERRUPTED不作正常完成耗时；无样本null；偶数取中间两值均值 |
| hint_rate | 终态非VOID轮中至少成功揭示一次提示的轮数 / 终态非VOID轮数；INTERRUPTED纳入，活动轮不纳入；分母0为null |
| invalid_ratio | 非VOID轮内本机已终态、可识别猜词尝试中业务拒绝数 / 已终态猜词尝试数；业务拒绝含格式/短码/轮关闭/重复/限流；系统失败单列不作invalid但保留在尝试分母；普通聊天非尝试、未判定/未终态不进分母；分母0为null |

| source_mode_counts | 各可信source_mode的本机去重源消息数（含聊天/拒绝），按provider_test再分区；空分区0，未知明确unknown；不是有效猜词计数 |

追加`attempt_outcomes={business_rejected:int,system_failed:int,successful:int,nonterminal:int,void_excluded:int,unassigned_round:int}`与`latency_missing_samples:int`，使分母可复算。没有分配到轮的猜词尝试（如IDLE短码）进入unassigned_round独立诊断，不加入轮质量比率；不能静默丢弃或归入当前新轮。VOID行仍在轮明细与void_excluded中可追踪，不能因为排除聚合而消失。积分另给`points_net:int`（账本含冲销净额），不可从猜词数重算。

MinuteRow固定`{bucket_start,bucket_end,partial:boolean,participants_count,valid_distinct_guesses,guess_attempts,business_rejected,system_failed,nonterminal}`。分桶以session.started_at起每60秒半开区间；末桶止于min(ended_at,captured_at)，部分分钟partial=true；跨分钟身份可在各分钟各出现一次，全场人数另去重。有效单元归属可信入场时间，迟评分在新快照补入原桶，不移到完成分钟；拒绝/非终态按本机接收时间分桶。观察窗口内无记录的分钟显式0，无观看数据不产生参与率。封账前VOID对应贡献在新快照排除，有明细说明；分钟数与整场有效计数可对账。

RoundAnalyticsRow固定`{round_id,round_ordinal:int,status,end_reason:string|null,puzzle_version_id,category_id,difficulty,has_anomaly:boolean,anomaly_codes:string[],trace_ref:string,started_at:timestamp|null,ended_at:timestamp|null,running_duration_ms:int|null,participants_count,valid_distinct_guesses,guess_attempts,business_rejected,system_failed,nonterminal,points_net:int,hints_revealed:int,completed_normally:boolean,included_in_aggregates:boolean,exclusion_reason:string|null,winner_display_name:string|null}`；VOID含exclusion_reason=VOID且points_net=0，未开始/未完成正常轮running_duration_ms可null。明细是私有历史统计，不含未揭晓answer/aliases/vector或原始UID。has_anomaly等于anomaly_codes非空；代码来自该轮本机已持久的gap/时钟/模型/中断/履约等异常，不凭总数推断。trace_ref为服务端不可猜测的轮追踪标识，解析时仍核diagnostics.read和场次归属；关联现有messages/trace查询，不含原始UID，轨迹保留期结束后返回410 TRACE_EXPIRED而聚合异常码继续保存90天。

分页默认50、最多100；新增GET `/api/v1/live-sessions/{session_id}/analytics/rounds?snapshot_id=...&cursor=...&limit=...` 返回`{be_extension_version,snapshot_id,items:RoundAnalyticsRow[],next_cursor,total}`；分钟分页沿原analytics GET用`section=minutes&snapshot_id=...&cursor=...`返回同型MinuteRow页。游标签名绑定snapshot/session/section/filter hash/limit/末键；轮按持久round_ordinal＋round_id升序，分钟按bucket_start升序，稳定键集分页，不用offset。非法/跨场/改limit/混section游标422 `ANALYTICS_CURSOR_INVALID`，快照不存在/过期/驱逐410 ANALYTICS_SNAPSHOT_UNAVAILABLE；无权查场次始终403，不能借ID探测其他快照。

CSV沿原GET `?format=csv&snapshot_id=...`，不得省略snapshot_id（422 INPUT_INVALID）。导出同一snapshot全量聚合、源分区、分钟、轮明细，固定`record_type`与字段列、metric_definition_version/snapshot_id/as_of/closure/coverage列；null空格、0为0、比率不擅自百分数化，文本逐单元做CSV引用与公式前缀转义。CSV不是只导当前页，也不现场重算最新值；权限/到期检查与分页相同。

#### 首版快照和CSV资源预算

同actor授权scope/session、过滤条件、metric版本与同一统计水位直接复用快照；不得靠轮询重复物化。新快照创建最短间隔为5秒/actor/session，间隔内默认返回既有快照并显式保留其as_of；请求`fresh=true`且超限429 `ANALYTICS_RATE_LIMITED`。无既存可返回快照时也429，不生成隐式超额副本。当前读请求响应可受通用速率限制，复用不豁免鉴权。

每actor/session最多16个有效快照，安装实例最多256个、全部物化总量≤1GiB；单快照分钟+轮明细总行数≤20000且物化序列化大小≤4MiB。生成前按受限计数/大小预算预检，生成中仍累计；超单快照预算413 `ANALYTICS_SNAPSHOT_TOO_LARGE`，不截断、不省略行伪装完整。预算失败不得回写业务状态。存储区为本产品私有临时位置，配额预留/释放原子化，崩溃后按归属清理未完成临时材料。

24小时为最长保留，容量不足可按LRU提前驱逐未pin快照；每actor/session第17份及安装第257份须先完成安全驱逐再创建。查询不存在/被驱逐/过期快照统一410 `ANALYTICS_SNAPSHOT_UNAVAILABLE`，details.reason区分EXPIRED/EVICTED/NOT_AVAILABLE，不默默切新snapshot续页。有效snapshot存在但无权限仍403；快照ID校验/游标格式错仍422。

分页/导出请求获得短租约pin，连续同一快照分页可续但从首次pin累计最长5分钟，单请求完成释放，超累计上限后重新获取需要检查是否仍存在，不无限保留。pin与驱逐串行核验；全被pin且无法腾容量503 `ANALYTICS_CAPACITY_BUSY`，不赶走使用者，也不突破配额。

CSV每actor最多1、安装实例最多2并发，超限429 `ANALYTICS_EXPORT_LIMITED`；单次≤32MiB、最长30秒，先预算预检再在冻结快照上流式读，无长业务锁。为使失败可观察，HTTP200/attachment header只在完整CSV写入私有受限临时文件且校验尺寸/时间成功后发送，下载再流式读取该文件；超32MiB为413 `ANALYTICS_EXPORT_TOO_LARGE`、30秒超时503 `ANALYTICS_EXPORT_TIMEOUT`，失败删除临时文件并释放pin/并发额度。完成/客户端断开也清理临时文件，不留原始私密导出副本。下载阶段IO中断不声称完整成功，客户端须重新校验响应长度，重试仍指向同snapshot。以上参数后续仅可由WP16/32实测证据及版本变更调整，不允许无界放宽。

验收反例BE-A15（T26/WT22、WP16）：空场计数0、所有率/时延null；同人跨分钟参与两次但全场只计一人；同词两人有两个有效单元；pending评分不入有效分母，完成后新快照补原分钟，旧snapshot分页/CSV字节内容不变；封账前VOID在新快照排除贡献且轮行保留；INTERRUPTED分母包含但不计正常耗时；page1后新轮/VOID不改变page2；篡改cursor/到期/撤权明确拒绝；manual/replay/test_live不能进入production分区。上述断言为实施验收要求，不代表验收通过。

### 17.4 下一题：权威预选、私有投影与一次消费

下一题是后端已持久化的候选，绝不是GET时重新随机或页面用题库列表猜测。`next_selections`最低字段：selection_id、session_id、version、status:READY|CONSUMED|INVALIDATED|EMPTY、puzzle_version_id:null|string、manifest_id/calibration_id:null|string、next_rules_version、selection_strategy:random|specific、selected_at、invalidated_at/reason、consumed_round_id:null|string、候选池revision。session最多一条有效READY；消费/失效历史保留审计。selection.version是session级永不回退的单调revision（持久计数器，初值0；无selection时ID=null但revision仍返回当前值），不能每建一行从1重置。READY/INVALIDATED/EMPTY/CONSUMED/替换及next_rules变化每次状态转换都推进该revision和session.version；同事务连续转换分别递增，提交只见最终状态。start必须使用最新session CAS，round create保留selection_id+revision，防止A→B→A的ABA。存储私有题目引用，不写relay/public事件。

候选池只含已发布、未禁用、审核/模型/校准匹配下轮规则的不可变版本；排除当前活动轮正在使用的puzzle_id（不是仅版本），不额外发明全场永不重复规则。题库/分类/难度、模型/校准、next_rules_version改变会让旧READY失效；同一题新草稿/新发布版本不会静默替换已选不可变版本，只有旧版本禁用或联合manifest不匹配才使其失效。

唯一新增命令走已有POST `/api/v1/live-sessions/{session_id}/commands`：`{command:select_next,expected_version,args:{strategy:random|specific,puzzle_id?:string,expected_selection_id:string|null,expected_selection_version:int}}`，须BE头、session.control＋场次归属、CSRF和Idempotency-Key。random由后端在事务候选池中均匀随机一次并保存实际ID（不得接受浏览器seed）；specific锁定指定题的当前合格已发布版本。expected_selection_id与expected_selection_version必须同时匹配当前选择与session级revision（无条ID=null、revision=0或既有计数），不能仅比较版本；并发改选只有一个成功，另一409 `NEXT_SELECTION_VERSION_CONFLICT`。成功用C1 CommandResult返回state含selection_id/version/status并返回最新session.version，不通过公开command详情泄题。

- start/人工round create的修改事务在无READY时可首次创建预选再消费；轮切换自动任务也调用同一用例。所有会影响候选资格或预选的事务（发布/禁用/联合manifest切换/configure/select_next/消费/触发自动重选）在事务最外层先取得本机PG事务级selection/catalog全局锁，再按稳定session_id→既有round→selection→稳定puzzle_id锁序执行，随后沿原participant/guess→ledger→event-counter顺序；新round在已锁session下插入。禁止已经持有session/puzzle再反向取全局锁；纯计分等无选题业务不取此锁，仍沿原锁序。批量修改统一排序，不持锁等待IO/模型/WS。组件只能调用统一选题用例，不自行追加另一套锁序。
- 创建新轮只消费一个READY，冻结该puzzle_version/manifest/calibration/rules，原子标CONSUMED并写consumed_round_id；网络/开窗失败后仍属于同一个PREPARING轮，重试不得再消费或抽题。幂等重试返回同轮。当前轮一旦冻结，后续禁用不改变当前轮，依原规则人工VOID。
- 轮进入RUNNING事务后自动为下一轮预选一次；auto_next=false也保存预选供手动下一轮。configure的next_rules修改、题目禁用/联合版本切换在原子失效旧选择后，自动以新候选池重选并保存（即使旧策略specific也不会继续使用已禁用题）；记录失效原因。有权限操作者可select_next主动改选，活跃轮不受影响。失败不吞掉旧失效原因。
- 自动任务不信已失效预览：消费时再锁定并核题目可用性与所有版本。若禁用事务抢先成功，旧选择INVALIDATED，当前消费返回409 `NEXT_SELECTION_STALE`，自动重新预选持久化后再调度新意图；不得在同一旧请求中换成另一题并声称消费了预览题。禁用与消费竞态只允许“先消费后禁用且当前轮冻结”或“先禁用旧选择不可消费”。
- 候选池为空，保存EMPTY且puzzle引用全null，reason=NO_ELIGIBLE_PUZZLE；无伪造题。auto_next停止于INTERMISSION，session仍ACTIVE并显示后台阻塞原因，不忙重试、不开空窗口。首轮start/round create不能完成则命令failed（start不进ACTIVE），409 `NO_ELIGIBLE_PUZZLE`；补充合格题后通过select_next或显式新意图重试。EMPTY在候选池revision或当前活动轮资格变化后允许受控重选；同一触发revision只执行一次，无变化不忙重试。自动重新选题事件/状态持久可恢复，不靠刷新触发。

每个受影响session的自动失效/重选在同一事务保存`system command`及现有STUDIO `command.updated`，系统actor固定`system:selection`，scope仍为该session；幂等键由`session_id+trigger_kind+trigger_revision`生成，绑定实际变更内容hash。command.state含旧/新selection_id、revision、reason和最新session.version，不含答案。命令状态在本机事务中applied，事务回滚连同revision/事件一起回滚；提交后outbox重投复用event_id、不再重选；重启扫描持久触发与command，未提交触发重跑，已applied仅补通知，即使没有round.*也不会静默变化。

私有投影追加到协商BE版本的SessionDetail及STUDIO快照：`next_selection={selection_id:string|null,version:int,status:READY|EMPTY|INVALIDATED|NONE,puzzle_version_id:string|null,category_id:string|null,difficulty:int|null,answer:string|null,aliases:string[],published_hints:HintDefinition[],explanation:string|null,next_rules_version:int,manifest_id:string|null,calibration_id:string|null,selected_at:timestamp|null,reason_code:string|null}`。HintDefinition=`{stage:1|2|3,text:string}`，这里是题目配置而不是PublicHint的已揭示时间。只允许session.control＋场次归属读取；状态非READY时answer等题目字段null、aliases/published_hints空。快照与next_rules/selection版本在同一次STUDIO一致边界读取，public_view白名单永不出现next_selection及其引用。答案仅在该私有响应；DISPLAY snapshot/WS、公开榜单、relay、日志/诊断导出不得含预选答案/aliases/私有ID。

BE round create请求增加`selection_id,expected_selection_version`，消费既存预览时二者必填，且旧strategy/puzzle_id若提供必须与保存选择吻合，否则409 `NEXT_SELECTION_MISMATCH`。没有既存READY且用户首次显式选择，允许C1原round create的random/specific创建并在同事务消费，响应带实际selection引用；有READY时缺选择引用返回409 `NEXT_SELECTION_REQUIRED`，不能随机覆盖预览。自动下一轮按持久选择引用调用同一用例；GET场次、GET private-state、GET STUDIO快照、GET题库都不生成/改选/消费。返回NONE表明尚未执行任何选择修改，不能因GET而变READY。

本节NEXT_SELECTION_VERSION_CONFLICT、NEXT_SELECTION_STALE、NEXT_SELECTION_MISMATCH、NEXT_SELECTION_REQUIRED、NO_ELIGIBLE_PUZZLE均为HTTP409、retryable=false；specific请求的不存在题目404 RESOURCE_NOT_FOUND，已存在但不合格409 NO_ELIGIBLE_PUZZLE；越权沿用403 FORBIDDEN，字段不合法422 INPUT_INVALID。命令异步失败沿C1 GET command返回HTTP200和error.code，不把失败状态包装为业务成功。
