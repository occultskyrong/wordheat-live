# 平台接入与运行约束：官方依据

核查日期：2026-10-25。范围为公开官方文档；未登录控制台、申请能力、启动任务、发送回调或连接真实直播间。以下事实不能替代指定账号、玩法和包体的实际接入验收。

## 1. 评论输入是否能实现自由猜词

- [直播间评论互动能力](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/jierushuoming/hudongshuju/pinglunshuju)：能力针对挂载玩法的直播间，需要申请开通，获取包含特定指令的评论。
- [创建直播玩法](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/zn/toybox-start)：平台采用已配置关键词的完整包含匹配；文档示例区分了不完整关键词和包含完整关键词的评论。能力申请、提案、包体发布是独立流程；答题类还提及官方题库能力。
- **方案推断**：将“猜”配置为参与指令、观众发送“猜 苹果”，可能让可变词语随原始评论传入。但公开页面不足以证明目标玩法一定能如此配置、审核通过且完整保留任意后缀。必须真实验证，不能把此推断标成已接通。
- **先行验证**：确认提案类型与题库要求；配置目标指令；由多个真实账号发送正常词、重复词、相似昵称、长词和非法格式；核对回调中的 content、msg_id、用户标识、房间和时间；确认完整词语、边界行为和展示反馈。若不成立，收敛为经确认的固定词表模式，或继续人工录入辅助模式，停止宣称自动直播闭环。

## 2. 消息可靠性与回调处理

[数据开放说明](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/develop/server/live-room-scope/data-open/data-open-desc)说明评论可能重复、乱序、丢失；评论没有礼物和粉丝团那样的失败回查保证。服务端需验签，并快速响应回调，不能等待模型推理后才确认接收。该页还给出推送时限及熔断条件，实施时按届时文档与账号实测值核对。

设计结论：验签 → 有界解析 → 持久化消息收件箱 → HTTP确认；推理与直播渲染在后续执行。内部保障从“本系统已持久接收”开始，不承诺平台端零丢失。使用 (platform, room_id, msg_type, msg_id) 去重；无稳定消息ID的第三方桥接只能声明近似去重。平台示例对时间单位存在文字与示例值不一致，适配器要保留原值及原单位、做配置化转换和异常检测。

## 3. HTTP确认与履约上报不同

- [玩法数据履约上报](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/jierushuoming/pingtaijichu/msg-ack-ability)：页面明确上线玩法需要履约上报；非Unity方案区分客户端收到与客户端处理完成两阶段。
- [互动数据履约上报接口](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/develop/server/live-room-scope/data-open/ack-data-report)：定义 ack_type、msg_id、房间与客户端时间等字段。

设计结论：HTTP 2xx仅表示回调已接收，不能伪称已在主播端展示。展示端需要返回接收与处理完成回执；服务端再进行可重试的履约上报。普通OBS网页不自动等于平台认可的客户端包体；正式玩法需要另外完成认可的包体/SDK或对应非Unity方案适配。

## 4. 展示与服务运行

- [OBS Browser Source](https://obsproject.com/kb/browser-source)：支持URL、视口尺寸、透明背景和页面刷新；隐藏来源可卸载页面，因此游戏状态必须由服务端持有，页面恢复后获取快照。
- [FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/)与[部署概念](https://fastapi.tiangolo.com/deployment/concepts/)：内存连接表示例只有单进程范围，多进程通常不共享内存。模型单独加载并设资源上限，房间状态由持久层约束。
- [PostgreSQL版本政策](https://www.postgresql.org/support/versioning/)：16仍属受支持大版本。方案选择16及受支持补丁，而非锁死本次网页出现的补丁号。
- [Node.js版本政策](https://nodejs.org/en/about/previous-releases)：方案构建工具选择24 LTS；实施时固定受支持补丁与依赖锁文件，不使用仓库旧运行时推定当前兼容性。
