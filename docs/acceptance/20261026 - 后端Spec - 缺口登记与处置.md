# 后端 Spec 缺口登记与处置（2026-10-26）

本文件回答一个问题：**当前仓库是否已按原 Spec 完整实现？** 做法是把 Spec §01–§17 与文末 C1 拆成可判定要求，逐条落到 `apps/api`、`apps/relay`、`apps/scorer` 的实际代码，再区分“真缺口 / 仅缺测试 / 误报 / 外部环境”。审计只读代码与制品，不采信注释与文档自述。

结论先行（2026-10-27 第二轮收口后更新）：**审计出的 6 类真缺口 O1–O6 已全部关闭**，修法与验证见 §1 的 G8–G13；§2 保留它们的修前判定与“为什么当时未改”的记录，便于复核。收口回归中另发现并修掉一处“测试与实现不一致”的真实失败（G14）。剩余未闭环项只有外部环境（§5 Windows/OBS/官方平台/G0/G1-R/G2/G1-Q）与“实现但本机无证据”的测试缺口（§3）。Mac 后端的接口面、契约与主链路按现仓库状态成立。

## 4 审计中判定为**误报**的项（附判定依据）

| 被指问题 | 判定 | 依据 |
|---|---|---|
| “评分预算实际可到 4 秒” | 不成立 | `lease_until=min(job.deadline_at, now+2s)` 恒 ≤ 受理+2s；提交阶段再校验 `completed-admitted>2s` |
| “`next_selection` 不应含答案” | 不成立 | §17.4 明确私有投影字段含 `answer/aliases/published_hints`，且要求 DISPLAY/公开视图不得含 |
| “`GET /puzzles` 已是一致读，说明其它 GET 也已修” | 不成立（反向结论） | `/puzzles` 早已 REPEATABLE READ；`/live-sessions/{id}` 等三个仍取行锁 → 已按 G1 修 |
| “relay `_close` 可能写入不一致的 close_seq” | 不成立 | `_close` 的 boundary 取当前 `last_seq`（即已提交水位），barrier 与其一致 |
| “会话可撤销缺失”与“登出即撤销” | 部分成立 | 登出确实使该会话失效；缺的是**对他人/全部会话**的撤销接口 → 记为 O1 |
| “`round_settlements` 主键不符” | 不成立 | 自有 id 主键 + `round_id` 唯一约束，语义等价“每轮一次终结” |

## 6 可承诺与不可承诺

- 可承诺：Mac 后端接口面与契约闭合（65 个 HTTP 操作、3 个 WS 协议、C1 45 基线全定义、`check_contracts` 报告 `valid=true` 且 `undefined_operations=[]`）；主链路、统计、回放、中继协议、模型与题库流程有真实 PG/真实模型/真实子进程证据；容量按 2 新词/秒 × 1800 秒实测；审计出的 O1–O6 已全部关闭并各有真实验证。
- 不可承诺：原 Spec 全项“通过”；Windows 可安装包；真实平台授权链；G0/G1-R/G2 与人工标注质量。
- 未做：逐条补齐 §3 的测试缺口（T2/T3/T6 仍只有代码而无本机负向/并发用例）。
