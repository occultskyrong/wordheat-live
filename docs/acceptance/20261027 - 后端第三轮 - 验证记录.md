## 3 契约

重新导出并校验：`valid=true`、`defined_http_operations=65`、`defined_websocket_protocols=3`、`defined_baseline_operations=45`、`undefined_operations=[]`、`errors=[]`。65 个 HTTP 操作比冻结轮的 63 个多出 `GET /api/v1/auth/sessions` 与 `DELETE /api/v1/auth/sessions/{session_id}`。

## 4 完成度工具状态

`source_matches=true`、`manifest_valid=true`、`contracts_complete=true`；严格整组 **3/100**（BE-A19、CONTRACTS-SUBSET、COMPLETION-TOOL），`all_complete=false`、`local_complete=false`。

`local_complete` 仍为 false 的原因不是缺证据，而是清单本身：local 组 21 项里 19 项（BE-04/BE-A04/T16 与 16 个 `BOUNDARY-*`）没有绑定实现路径与验证节点，工具按设计判 `not_implemented`。本轮不新增绑定——把未覆盖的整组标成通过正是该工具要防的事。

组件结果：166 条已重新取到证据（integration 115 条 passed、test 49 条 passed），另有 2 条仍为 stale（历史整批 `apps/api/tests`，见 §5）。

两处清单漂移已修：

1. `CONTRACTS-SUBSET` 绑定了一个已不存在的测试节点 `test_current_contracts_are_valid_partial_subset`（现为 `test_current_contracts_define_all_current_backend_wires`）。这会让带 root 的清单校验恒为无效，进而把所有 `required_environment='local'` 的条目压成 `not_implemented`。已重绑。
2. 106 条组件子场景仍锚定 2026-10-26 00:39 之前的测试文件哈希，而这些测试在迭代二后续被修改过（relay 组件测试还是本轮 G10 改的），导致它们此后无法再取到证据。已按当前文件重新锚定并重跑对应批次，不是放宽校验。

## 5 本机环境与耗时说明

收口期间本机 load average 约 10，另有 kafka/mongodb/mysql/nacos/postgres/rabbitmq/redis/nginx 等容器在跑。数据库微基准 `select 1` 为 0.91 ms/次，不存在数据库退化；集成套件变慢主要来自 CPU 争用。

历史整批 `apps/api/tests`（174 个用例）在 2026-10-26 用 46s 跑完；当前同一目录为 331 个用例、约 820s，其中相当部分集中在少数重用例（各 200 次 HTTP 只读读的选题用例、真实子进程 runtime 用例、真实工作流用例）。验收 runner 的执行预算是固定 120s 且不接受自定义参数，因此本轮改为按子目录/文件分批重取，历史整批条目 `apps/api/tests` 保留为 stale 并在此说明原因，不用小批量结果冒充整批通过。
