# 后端接口修复与复核（2026-10-27）

结论：本轮确认的四处后端接口缺口已全部修复并落入实际仓库。定点回归、契约检查和独立接口复核通过；按当前后端接口清单复查，未发现其他未实现路由、空业务处理或缺少必要任务执行链的接口。本结论只针对接口代码实现，不扩大为性能、前端或平台放行结论。

## 四项修复

| 原问题 | 修复后的接口行为 | 回归证明 |
|---|---|---|
| `DELETE /api/v1/auth/sessions/current` 被动态路由遮蔽 | 静态退出路由优先匹配，实际撤销当前 token 并清除 Cookie；按 session ID 撤销接口保留 | 实际路由调用、退出后当前会话失效、Cookie 清除、普通会话 ID 撤销 |
| CSV 确认和查询缺少新草稿 ID | 命令 state 返回 `{validation_id,operation,puzzle_version_ids}`；任务查询返回 ID 集合，命令查询与幂等重试一致；旧成功缓存只读补齐，禁止重建草稿 | 确认/任务/命令三个结果一致、空/单/多 ID、幂等与旧缓存、取消、越权不泄露 |
| official 快照和心跳固定为本地离线 | DISPLAY、STUDIO public_view、WS heartbeat 共用真实只读连接状态投影；实际状态变化产生 `connection.status` | 正常状态与故障状态映射、两类快照/双 WS、双 audience 连续游标、重复状态不重发、事务回滚原子性；GET/心跳不造事件或发网络请求 |
| relay WS 展示回执无真实时间，后续履约失败 | BE1.1 展示回执携带真实 `client_time`，入队前校验，持久传至 SDK 适配器；旧缺字段帧明确拒绝而不假 pending | 两阶段实际 WS→专库→worker→模拟 SDK；缺/坏时间不写 stage/job、版本/旧连接拒绝；正常传输 ACK 不回归 |

同一连接快照调用链中还修正了 `pending_commands` 在只读事务申请行锁导致 official STUDIO 返回 503 的问题，这是第三项读取链闭合所需修正。

独立复核另发现 HTTP/WS 反向重投不对称：先用 WS 保存事实，再以不同处理时间从 HTTP 重投时曾错误返回 accepted。本轮已补齐双向校验：同一 SDK 毫秒幂等，异时返回 `409 RECEIPT_CONFLICT`；显式 retry 不能改写已保存的处理时间，原 HTTP 字符串不被覆盖，不重复上报。

## 契约与兼容

- 新 `ImportCommandState` 为有类型的命令结果；`ImportResult` 明确携带 `puzzle_version_ids`。
- `Transport.state` 保持 C1 原五态：DISCONNECTED / CONNECTING / CONNECTED / RECONNECTING / FAULTED；新增实际 `ConnectionPayload` 对应事件 Schema。
- WS 展示回执要求握手头 `X-BE-Extension-Version: LW-BE/1.1.0`，帧为 `{kind,stream_seq,receipt_id,client_time}`，时间为 UTC 毫秒 `YYYY-MM-DDTHH:mm:ss.sssZ`。缺/未知扩展、缺/非法时间、冲突事实按现有 `relay.error` 与关闭机制明确拒绝，不生成虚假成功或 pending。
- `transport.persisted` 保持原有行为；现有 HTTP delivery-stages 的 ISO 时区/精度兼容保留。缺真实时间的历史坏任务不会被自动补造时间。
- OpenAPI、两类 WS Schema、导入响应模型、源码 inventory、正反例与兼容说明已同步；[详细兼容说明](../../packages/contracts/20261027-interface-compatibility.md)。
- 原后端 Spec SHA `6c582420ea7d80d66cea1178e8629e7358a6a23a88c1d5ea65843a47f821f63b` 与历史 C1 SHA `d69ae165a6d1169e00f20bb03b4cd66bdc9ed2fe7ef2a730c2a130934a88b4e8` 保持不变。
