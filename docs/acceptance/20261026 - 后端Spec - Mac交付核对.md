# 后端 Spec · Mac 交付核对

状态：已冻结（2026-10-26），并于 2026-10-27 完成第二轮收口与收口回归：原登记的真缺口 O1–O6 已全部关闭（撤销接口与 `disabled_at`/`guesses.epoch` 迁移、relay 组件测试装载、official 时延采样、6 秒失联与 30 秒传输预算覆盖、短码耗尽判定），契约由 63 个 HTTP 操作重新导出为 65 个并通过 `check_contracts` 全项校验；收口回归另发现并修掉一处“测试与实现不一致”的真实失败（G14：模型探测新鲜窗口 2 秒断言 vs 5 秒实现，窗口已提为具名常量并由测试钉住两侧）。Mac 后端功能、容量声明与逐项证据按本文件记录；**缺口处置明细另见[缺口登记与处置](20261026%20-%20后端Spec%20-%20缺口登记与处置.md)**（O1–O6 的修前证据、修法与验证），**收口回归的逐项数字另见[第三轮验证记录](20261027%20-%20后端第三轮%20-%20验证记录.md)**。Windows/OBS、官方平台与 G2 仍按表内边界取证，未由本机结果替代。

依据原始《后端开发 Spec》v1.1（SHA-256 `6c582420ea7d80d66cea1178e8629e7358a6a23a88c1d5ea65843a47f821f63b`），历史C1 SHA-256 `d69ae165a6d1169e00f20bb03b4cd66bdc9ed2fe7ef2a730c2a130934a88b4e8`。本记录逐条解释原规范的后端落实、执行证据和实际环境边界，不重新发明完成比例。

## 完整执行链

真实离线模型HTTP链：草稿 → calibration → 锁定blind → 审核/发布 → CREATED → primary快照/WS Ready → start/首轮 → 异步评分 → 精确别名胜出 → 自动下一轮 → pause/提示/resume/VOID → end → trace/统计/CSV；回放使用独立场次、时基和来源分区。

双端协议链：批量验签回调 → relay事务落盘 → HTTP确认 → TCP WebSocket不可变frame → 本机持久确认 → 有序入场/评分/终态 → 展示协议received/processed → 独立SDK ACK任务 → 失败重试/停任务/释放租约。所有合成来源保持provider_test，SDK使用公开向量和MockTransport，不签发真实平台通过证据。

维护链：原生身份/权限 → prepare/审阅/确认 → 一致快照备份 → 严格归档验证 → 独立逻辑库恢复与数据摘要 → 恢复身份失效；签名M2清单 → 回收M1进程 → 新boot/私有密钥/实际M2预热 → 新资源导入/联合激活 → 数据指针 → 正常stop。两份真实BGE部署manifest使用相同权重，证明部署切换机制，不声称训练或神经权重变化。

### 本轮定位与修复

1. **GET 快照不再占用会话行锁**：DISPLAY/STUDIO 快照改为 `REPEATABLE READ` + `READ ONLY` 一致读，`snapshot(lock=False)`。此前 GET 走 `engine.begin()` 并对 `live_sessions` 取 `FOR UPDATE`，与入场/结算在同一行锁上排队；实测该语句是采样中最大的 tuple 锁等待来源。改后 `as_of_seq` 与投影同属一个 MVCC 快照，读请求也不再加行锁、不阻塞业务写入。
2. **模型健康探测容忍单次瞬时失败**：此前一次取证超时即把 `ready` 置 false：中止运行中先出现 3 次模型健康 503，随后回合 worker 将活动轮判为 INTERRUPTED，其后 881 条输入落入轮间拒绝。现改为连续 2 次失败或成功观测超过 5 秒才判定不可用，仍为 fail-closed；真正宕机在约两个探测周期内停止接纳与结算。
3. **提交时延观测只针对已持久化猜词**：被拒绝的入场只在 `guess_rejections` 落库，其 id 不属于 `guesses`；此前仍写 `analytics_latency_observations`，触发外键错误并使观测事务反复回滚。
4. **导出目录创建容忍 EEXIST**：`exist_ok=True` 在本机文件代理下仍可能抛 EEXIST；现先确认是目录再继续，后续 `lstat` 的属主/权限检查不变，残余失败映射为受控 503。
5. **并发入场上界保持 4**：曾试 8，300 秒同速率探针的 p95 由 509ms 升到 1128ms（同槽位内更多事务争同一会话行），且与既有 `test_bounded_ingress` 的容量假设冲突，已回退；该上界是资源保护，不是吞吐旋钮。
6. **其余只读 GET 同样不再取行锁**：`GET /live-sessions/{id}`、`GET /rounds/{id}/private-state`、`GET /commands/{id}` 原走 `engine.begin()` 且对会话/回合取 `FOR UPDATE`，现改 `read_snapshot()` + `lock=False`；锁采样确认它们此前与入场/结算同队。
7. **官方模式迟到的赢家会向中继确认**：relay 在 TIMEOUT 屏障后仍接受“赢家落在原 close_seq 内”的幂等 close；本机此前在 `close_seq` 已置时直接跳过，导致赢家只在本机成立、中继无记录。现始终以 `SOLVED+winner_seq` 确认。
8. **readiness 时间格式符合 §03**：`evaluated_at` 由微秒 `+00:00` 改为毫秒 `Z`。
9. **relay WS 帧上限**：uvicorn `ws_max_size` 显式设为 1MiB，与 §08 单帧上限一致。
10. **official 场次可以封账了**：原封账门要求 facts 里存在 `unresolved_gap` 键，但全仓库没有前置写入，导致正式场次永不封账（统计不冻结、7/30/90 保留不推进）。改用连接器真实发布的 `relay_coverage=='complete'` 作为放行证据，其余 fail-closed。
11. **`select_next` + `specific` 的错误码对齐 §17.4**：选到“存在但不合格”的题此前静默返回成功 `EMPTY`，现返回 409 `NO_ELIGIBLE_PUZZLE`；不存在 404、缺 `puzzle_id` 422。

修复后 2/s × 1800 秒复验：3534 条全部 `scored`、0 限流、0 依赖失败、0 RESULT_STALE，8 轮（7 次 TIMEOUT 自动续局 + 1 轮在跑）按原语义完成；说明健康探测的容忍与快照一致读没有削弱失败可见性，也没有把拒绝改写成成功。

### 测量口径与限制

- 负载工具与 API 同进程（16 个发送线程 + 真实事件循环 + 真实 DISPLAY 协议消费者），p95 含测试进程的 GIL 竞争，属保守估计；发送按真实时间节拍，不使用虚拟时钟，不放宽任何断言。
- 输入为合成汉字，`source_mode=bridge`、`provider_test=true`；不产生 production 统计，也不构成 G1-Q/G0/G1-R/G2 证据。
- 数据库为已登记的 DLC PG16 专库，数据目录位于容器绑定挂载。本轮观测到 `checkpoint write=260.098s / 318 buffers`（11:21:26→11:25:47，`checkpoint_timeout=5min`）；存储停顿是 30 分钟尾部时延的主要外部因素，也是声明容量低于原目标的主因。Windows 原生服务的本机 NVMe 目标须按 WT08 独立复测，不复用本机结论。
- 每轮拒绝、评分失败、轮间拒绝与真实时延均按原语义计入报告；`accepted_without_processed`、`pending_at_end` 与来源分区同时核对，未把协议 processed 当作画面渲染或官方履约。
