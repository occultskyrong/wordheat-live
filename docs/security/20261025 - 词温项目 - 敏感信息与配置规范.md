# 词温 · 敏感信息与配置规范

适用：Windows 原生本地部署＋轻量公网中继方案 v1.1。本文约束后续开发和交付，不改变 LW-C1 协议、DPAPI 引导与运行期凭据机制。

## 当前实施与证据范围

初始安全审查覆盖方案、Spec、计划、研究资料、图稿和 HTML 构建器；当时尚无应用运行实现。该历史静态审查在其覆盖的非 Git 文本、图像元数据及生成 HTML 中未发现真实平台密钥、私钥、访问令牌或含密码的连接串，并脱敏了迁移清单的两处本机绝对路径；它不是本轮全部后端代码或运行期的完整安全审计，也不证明任何编码或隐藏凭据均不存在。

当前后端已存在 API/relay 配置加载器、运行/迁移身份校验和配置测试。API 根 `.env` 与 `deploy/public-relay/.env` 被 Git 忽略、POSIX 权限为 0600，已分别配置本项目专库字段；只提交空值 `.env.example`，不把“模板空值”误写为“实际环境没有配置”。API 和 relay 从明确配置源按自己的最小白名单读取，运行角色与迁移角色分离。

本机开发/测试复用 DLC 已登记 PostgreSQL，专库为 `wordheat_test` 与 `wordheat_relay_test`；不能借用其他项目数据库、移动该既有实例的数据 bind，或把容器/数据库技术可用当作变更授权。实际组件结果和未验收边界见 [本轮后端验证记录](../acceptance/20261026%20-%20后端迭代%20-%20验证记录.md)，其中的 PG/配置测试不替代 Windows、正式平台或完整运行期安全验收。

复制仓库或首次克隆不会得到私有 `.env`，由各环境负责人从模板另建并填入。实际值、连接串、密码与平台密钥不写入源码、文档、报告或发行包；当前规则不授权读取或展示这些值。

## 架构与保存位置

| 对象 | 位置与消费者 | 规则 |
|---|---|---|
| 本地开发 API 数据库连接 | 根 `.env` 的 `LOCAL_DATABASE_URL`；仅 API 进程 | 使用专用运行角色；缺失即拒绝相关服务启动 |
| 本地开发迁移连接 | 根 `.env` 的 `LOCAL_MIGRATION_DATABASE_URL`；仅迁移进程 | 与运行角色分权；加载器只向迁移组件提供该字段，不整体转发环境 |
| 中继持久库连接 | `deploy/public-relay/.env` 的 `RELAY_DATABASE_URL`；仅 relay | 与 Windows 库隔离；不复用本地运行凭据 |
| 官方应用标识与密钥 | 中继 `.env` 的 `DOUYIN_APP_ID`、`DOUYIN_APP_SECRET`；仅平台适配器 | app_id 按内部配置统一管理，app_secret 必须保密；实际参数绑定由 G0 官方验证确认 |
| 独立回调验签材料（若平台要求） | 仅加入中继私有 `.env` | 公开协议使用独立 DOUYIN_PUSH_SECRET 验证回调；请求 access-token/RSA profile 分开，实际授权与来源由 G0 取证；模板只含空值 |
| Windows 发行版数据库运行凭据、设备长期授权 | 用户级 DPAPI 密文＋显式 ACL | 依后端 Spec 第 12 节安全引导；不得随发行包携带明文 `.env`，迁移凭据不交运行用户 |
| Launcher/API/scorer 每次启动密钥 | 受限句柄或本机管道交付，进程内存保存 | 不进入 `.env`、进程环境变量、命令行、日志或磁盘明文；随 boot 轮换 |
| 登录密码与会话 | 密码经认证边界处理后仅持久化 hash；会话依 Spec 使用服务端状态和 HttpOnly Cookie | 不将用户密码、Cookie、CSRF、展示票据或短期设备 token 固定写进 `.env`；浏览器恢复仍按角色分别执行 |
| 代码签名私钥与证书密码 | 专用签名环境的秘密存储或私有挂载；密码可由该环境私有 `.env` 注入 | 不进入源码、Windows 安装包、模型包、构建日志或文档；PE 中公开签名证书不等同私钥 |
| 非秘密前端配置 | 经白名单下发的 API 地址、功能开关、版本 | 不含平台凭据、DB DSN、设备令牌、scorer 启动密钥或未揭晓答案 |

模板字段为配置输入约定，当前 API/relay 加载器已消费各自白名单字段；已实现的公开平台适配使用独立 secret/profile；Windows 引导按相应工作包实机验证。`WORDHEAT_ENV` 仅表示部署环境，不能用于信任浏览器传入的 `run_purpose`，也不能授权正式直播。

## 开发执行规则

1. 各进程从明确指定的配置源读取所需字段，不扫描上级目录、不合并本地和中继 `.env`、不把整个父进程环境转发给子进程；文档构建进程不加载私有配置。生产中继可用受控云环境变量注入同名字段；如使用文件，放在私有部署目录并显式指定。
2. 加载器在启动入口校验必填字段、连接目标与角色。空值、示例值、权限不符或配置缺失时关闭相应服务/连接能力，错误只显示缺失字段名，不打印原始值，不回退到公共默认密码或跳过验签。数据库运行角色不能执行迁移。
3. `.env` 是明文隔离文件，不提供加密能力。在 POSIX 环境使用 0600 与私有父目录；Windows 开发/中继环境用 NTFS ACL 限定当前用户或服务身份及必要维护身份。Windows 发行版继续使用 DPAPI，不把 0600 等同 Windows ACL。
4. 前端不加载根目录或中继的私有 `.env`。任何秘密都不得以 `VITE_` 前缀、`define` 替换、`import.meta.env`、静态 JSON、HTML、source map 或 OBS URL 注入浏览器；不能设置空 `envPrefix`。Vite 会将带 `VITE_` 前缀的变量暴露到客户端代码，详见 [Vite 环境变量文档](https://vite.dev/guide/env-and-mode) 与 [envPrefix 配置](https://vite.dev/config/shared-options#envprefix)。
5. 日志和错误输出采用字段白名单。密码、Authorization、Cookie/Set-Cookie、平台 secret/token、完整 DSN、带票据 URL、原始平台 UID 与私密载荷均不得直出；日志只保留 reason_code、request_id、内部脱敏标识和状态。诊断导出与截图采用同一边界。
6. 安装器、前端、模型包和文档导出按发布白名单收集，不递归打包仓库。排除 `.env*`、`*.env*`、secrets 目录、私钥与含用户数据的日志/备份；必要公开证书单独审核。HTML 构建器会全文内嵌 `docs/research/*.md`，分享前同时审查源文件与生成 HTML。
7. `.gitignore` 覆盖各层私有 env、秘密目录及私钥/证书容器；唯一 env 模板例外是空值 `.env.example`。不要用 `git add -f` 提交秘密。Git 忽略只影响未追踪文件，不能清理已追踪文件或历史；发现真实凭据被提交时，先撤销/轮换，再按影响范围清理历史。见 [Git 官方说明](https://git-scm.com/docs/gitignore)。

## 后续开发验收

| 验收项 | 落点与通过标准 |
|---|---|
| 配置加载与权限分离 | API/relay/迁移已有代码和配置/真实 PG 组件测试，见本轮验证记录；空秘密拒绝、角色隔离、进程不获得无关密钥仍为持续验收标准，不能据组件通过宣布全部运行期安全完成 |
| 前端/安装包隔离 | Web 构建与 Windows 打包任务；仅在隔离测试配置中使用合成哨兵值，确认 JS/HTML/map/EXE 资源与模型包中均无哨兵；当前待实现 |
| 日志与诊断脱敏 | API/relay/launcher 错误及导出用例；模拟 DSN、header、平台响应中的合成秘密不出现在输出；当前待实现 |
| Windows 凭据闭环 | 真实 Windows SID/ACL、DPAPI、引导失败与重试；遵守后端 Spec，不能由本次静态审查替代 |
| Git 提交与分享 | 每次检查待提交差异、env 忽略命中、模板无真实值，并扫描文档和生成文件；真实凭据不进入 Git |

已有前后端 Spec 的认证、CSRF、公私 DTO 和直播验收要求继续有效。配置文档与忽略规则只能建立仓库边界，不能视为运行期或真实直播验收通过。

## 当前 Mac 原生与中继运行补充

Mac 设备长期 seed 仅保存于根 `.env` 的 `LOCAL_DEVICE_PRIVATE_KEY_B64URL`，配对 ID 为非秘密字段；设备短 token、平台短 access token、launch token 和每次启动密钥仅在内存/受限通道。Mac 原生 UID/PID/socket 验证不等同 Windows DPAPI/SID。

relay 的服务器 freshness 私钥只在独立 relay `.env`，对应公钥必须独占 freshness_proof 用途。平台 AppSecret、推送 secret、身份 HMAC key、RSA 请求私钥和平台响应公钥分别校验。可信根与候选部署 allowlist 不能生成 gate、RC 或正式授权。

维护工具注册表仅含固定本地 Unix 传输、程序摘要、容器/专库/角色及源/恢复目标；无 DSN/密码，仍按当前用户 0600 保存。原生确认后的迁移只应用当前安装包的已知 checksum SQL，使用登记迁移角色；API 运行 DSN不获取DDL能力。当前完整备份要求可信迁移摘要与固定保护函数/trigger，旧schema明确要求兼容迁移，不能依归档自述放行任意函数。
