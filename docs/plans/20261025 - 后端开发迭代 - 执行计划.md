## 第二轮增量与严格边界

BE-A19 补强旧预选 ID/revision、全局 catalog→稳定 session 锁顺序、无 round 事件时的持久系统通知、触发内容哈希与回滚/重启幂等、EMPTY 仅随新触发重选。新增 18 个真实 PG 测试；BE-A16 只记录实际覆盖子场景。

BE-A20 增加事务内 final 持久化和独立匿名 trace 载荷，新增 19 个真实 PG 测试。业务事务先增 counter 再持久化 final；GET 不封账/修复。新查询叠加当前 as_of 与投递诊断，durable final 的业务依据与旧 snapshot 不变。超预算提交 ENDED、保留 raw/ledger，标记物化 pending，GET 返回 413，不截断或假封账。非预算异常仍回滚业务事务。

A20 整组保持 partial：official ACK 查询为 503；超大 final 没有完整恢复 worker；没有自动 7/30 天清理 scheduler（仅显式 session 范围 trace prune 和安全 fixture 清理）；旧未观察且未封账的 GET-only HMAC trace 引用仍有限制。30 天 trace 410 与 90 天聚合恢复按新测试的局部证据记录。

验收清单 boundary v2 只扩展 A19 四个精确依赖，并绑定 13 个 full-verification 节点；A20 full-verification 仍为空。独立组件复核与最终可信 runner 结果分别记载，不能互换。正式主 4 批共 294 个唯一测试通过（API 174、relay 46、scorer 32、tools 42），0 失败、0 跳过；150 个组件子场景全部通过。严格整组为 3/100，BE-A19 passed、BE-A20 pending_external，`all_complete=false`。

## 验收工具语义

`packages/contracts/check_contracts.py` 检查历史 C1 字节、版本/Spec 绑定、已定义操作与 Schema。退出 0 / `valid=true` 仅表示已定义子集合法；`all_contracts_defined=true` 才表示定义齐全，仍不代替实现或外部验收。

`scripts/backend/20261025-check-completion.py` 有三种用途：

- 不带运行参数：读取严格整组清单与所供报告。默认退出 0 表示 `all_complete=true`，退出 1 表示未完成，退出 2 表示输入错误。`--local-only` 只改变退出码依据为 `local_complete`，不改变全清单 `all_complete` 的计算。
- `--run-tests`：对已有仓库测试路径执行固定 argv 的 pytest collect 和 JUnit 运行，不执行清单里的 shell/command。逐服务使用所属 `.venv` 启动检查器；跨服务同一批次直接拒绝。`--environment` 是调用者声明，`observed_runtime` 另外记录实际系统、解释器、服务和运行目录。环境资格不符、跳过、空套件、失败均不能标组件通过。
- `--report` 可重复传入实际 `evidence.json`；`--write-progress` 汇总到固定 `docs/acceptance/backend-progress.json`。该操作退出 0 只证明汇总写入成功。`--run-tests` 也保存本次证据并刷新进度，不能把写文件成功当验收通过。

例如本地 contracts/tool 证据运行：

```sh
cd /Users/jiachenclaw/code/wordheat-live
apps/api/.venv/bin/python -B scripts/backend/20261025-check-completion.py \
  --root /Users/jiachenclaw/code/wordheat-live \
  --run-tests packages/contracts/tests --run-tests scripts/backend/tests \
  --environment local
```

每次生成 `docs/acceptance/backend-evidence/<run_id>/`，含 `collection.txt`、`output.txt`、`results.xml` 和 `evidence.json`。使用返回的真实 `run_id` 和报告路径进行后续汇总，不能复制其他候选目录的报告冒充当前执行。

报告绑定当前精确 Spec、清单/实现/测试源与 JUnit 附件摘要、真实 collect 节点及带时区执行时间；同节点最新失败覆盖旧成功，同刻冲突失败关闭。工具只 AST 读取测试源，不导入测试来猜节点；参数化节点未经精确绑定不假定实例 ID。报告是可信执行者提供的证据，不是密码学执行证明。

进度文件 `full_spec` 保存 100 项严格整组状态；`component_results` 汇总批次与子场景，单批 `evidence.json` 另有 `subcase_results`。`group_refs` 不升级整组。`entire_acceptance_group_complete`、`whole_stage_complete` 保持严格边界；runner 不自行宣称独立验证。Spec、实现、测试或附件漂移时证据转为 stale/unverified。通用 runner 不具备 Windows/OBS/平台专项能力，即使调用者声明外部环境也不能代替专门取证。

`pending_external` 表示整组尚无满足其环境要求的完整证据，不表示当前 PG/model 缺失；已有真实组件结果。整组 implementation/verification 尚需逐项补齐，不把未通过项统一归因于外部环境。
