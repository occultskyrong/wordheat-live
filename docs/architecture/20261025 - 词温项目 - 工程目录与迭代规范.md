## 目录边界与依赖

| 工程 | 输入/依赖 | 持有的职责 | 不进入此边界的内容 |
|---|---|---|---|
| Web | 契约生成类型、本机 API、分角色事件流 | 八类页面、投影、交互、真实展示回执 | 平台密钥、评分/判胜、数据库、原始平台 UID |
| 本机 API | contracts、独立本机 PG、scorer、relay 协议 | 谜底、入场、回合、账本、公私快照；唯一 relay 连接 | 在浏览器计算权威状态；共用 relay DSN |
| scorer | 固定模型 manifest、本地模型文件、内部认证 | 编码、批处理、有限资源与版本校验 | 判胜与账本、前端直连、公网模型接口 |
| relay | contracts、独立 PG、官方接入、私有部署配置 | 验签持久收件、所有权、窗口、可靠投递与独立履约 | 指定题目的答案映射、本机积分权威、远程 shell |
| Windows launcher | 冻结发行包、受控本机 IPC、OS 身份 | 原生状态、进程 Job、安全引导与维护 | 第二个 WSS 消费者、浏览器提供的任意命令/路径 |
| deploy | 已构建应用、审核资源和发行摘要 | 安装/部署/升级/验证材料 | 业务规则副本、私钥、私有 `.env` 的发行副本 |

API 的业务模块为 auth、sessions、rounds、inbox、wordbank、scoring、ranking、realtime、connectors、replays、analytics、operations。适配层依赖用例和领域接口，不能由平台适配直接改榜单。contracts 不依赖 apps；评测工具不构成运行期业务依赖。

Web 八类页面保持前端 Spec 的 setup/studio/obs/words/scoring/replay/analytics/settings 路径；公开与私有 API 类型未来同处 `src/api/generated/` 但依赖白名单必须分开。目录并存不代表允许 public 导入 private。

## 已确定的路径差异处理

- 原方案示意 `infrastructure/outbox/`，WP10 明确实现 `infrastructure/outbox.py`；本骨架保留后者的文件位置，不建同名目录。
- 原方案 API `modules/guesses/` 的输入职责以较新后端 Spec 的 inbox/rounds/scoring 划分，不增建重复业务层；前端 `features/guesses/` 按前端 Spec 保留。
- 旧方案的共用反馈组件按前端 Spec 放入 `features/guesses/` 等具体功能位置，不额外创建 `components/feedback/` 并行实现。
- WP08/WP20 共用 `resources/model-manifest.json`，不能分成两份；当前该清单已存在，记录真实本地 BGE 文件摘要；`quality_gate=not_evaluated`，不能据文件存在视为 G1-Q 通过。
- 本轮只覆盖 P-W 首发，P-A 的 `deploy/remote-core/` 留待范围明确后建立。API/scorer/relay 当前已有独立 `pyproject.toml`、`uv.lock` 与 `.venv`；CI/Windows 构建仍按 WP04 冻结与验收，不以本机依赖锁推定发行完成。

若后续 Spec 与工作包出现新的语义冲突，先核对共同契约及责任边界，再同步设计与清单；不能只靠本目录文档覆盖协议。

## 配置、运行数据与交付

沿用 [敏感信息与配置规范](../security/20261025%20-%20词温项目%20-%20敏感信息与配置规范.md)：开发 API 的根 `.env` 与 relay 的 `deploy/public-relay/.env` 分离，只提交空值 `.env.example`；Web 不加载这些秘密，Windows 发行继续使用 DPAPI 与内存密钥。当前 API/relay 私有文件已配置本项目独立专库所需字段，由各自白名单加载；秘密不进入文档或发行。
